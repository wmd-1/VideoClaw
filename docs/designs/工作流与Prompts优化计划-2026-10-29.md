## 一、目标与非目标

### 目标

1. 用户修改的内容与实际提交模型的内容一致。
2. 上游正文、场景、资产选择和时长在阶段间不丢失、不被旧结果悄然覆盖。
3. H3 改写与视频执行使用相同的素材、顺序、模式和有效参数。
4. 人物／非人物、中英文、生成／导入／续写采用一致的内部契约。
5. 在不降低保真、可控性和历史恢复能力的前提下，减少重复请求与冗余上下文。
6. 区分“未评估”“相对最好”“绝对合格”，并使优化收益可测量。

### 非目标与保护边界

- 不引入新的 Agent 编排框架，不替换现有主工作流，不更换模型供应商或默认模型。
- 不在本轮接线修复中启用 `temperature` 透传；维持既有“当前未生效、预留”的语义。
- 不删除上传原文、历史视频／图片、人工选择和非目标条目；不通过清空产物解决失效问题。
- 不把旁白变成出镜人物，不把静态首帧模板与动态视频模板合并。
- 不取消分镜硬校验、H3 有界重试或 Doctor 错误分流；不以放宽校验制造通过率。
- 不改写官方指南来源副本，不凭无引用扫描直接删除兼容模板。
- 不预先承诺节省百分比；真实模型调用和费用需单独授权。
- 不自动提交、推送、归档 OpenSpec 或连续执行多个未经确认的 change。

## 三、实施前需确认的建议决策

以下是推荐方案，不表示用户已经拍板。确认后写入对应 OpenSpec；未确认前不执行。决策使用 Q1～Q7 编号，与阶段任务 A1～D5 区分。

| 决策 | 推荐方案 | 不建议直接采用的替代方案／原因 |
|---|---|---|
| Q1：实际提示词来源 | 视频页显式保存形成“人工有效正文”；无人工正文时使用新鲜 H3 结果，再按既有规则回退；前端展示实际提交正文及来源 | 只改 `description` 而保留隐藏覆盖；或取消 H3 优先级，破坏已有改写功能 |
| Q2：有效参数与失效 | H3 和视频共享解析结果；素材／模式／时长／风格／权威事实发生语义变化时标记派生产物需重算，历史仍可查看 | 下游适配器静默改变参数；或上游一改就清空所有下游资产 |
| Q3：评估不可用 | 标为未评估／评估失败，可人工使用已有候选；相对选优不自动等于绝对合格，不填造分数 | 统一判通过，或评估异常就无界重生图 |
| Q4：语言与资产类型 | 语言显式保存，旧数据只在统一入口推断一次；资产类型由共享 schema 承载，生成与评估成对路由 | 每阶段按标题猜语言；只修改人物生成模板而不修改评估模板 |
| Q5：grounding 缓存 | 会话隔离、进程内有界缓存；缓存键含模型／策略与图片内容指纹；不在本轮承诺跨重启命中 | 无界进程全局字典、跨用户共享未经授权内容、为缓存另建基础设施 |
| Q6：连续性摘要预算 | 先计量，保留当前全历史摘要作为对照；通过独立规格与质量评估后再采用受限上下文 | 直接截断全部前序摘要，违反现行规格并丢失远距离连续性 |
| Q7：H3 规则冲突 | 按现行规格统一事实优先级；明确项目规则覆盖指南通用示例，保留指南原件和校验约束 | 删除校验以提高通过率，或擅自改变用户意见与权威事实优先级 |

验收：mock 正常合格、正常不合格、超时、非法 JSON、非法候选索引；精确断言状态、实际调用次数和循环边界。阶段完成、资产可用和质量合格三者分别断言。

## 五、阶段 B：H3 与视频共用有效输入

### B1｜建立共享生成请求快照（WF-05／07、OP-04）

主要落点：`prompt_rewrite_agent.py`、`video_agent.py`、`models/custom_video.py` 及现有参数／媒体解析公共层。共享解析器的正式名称和文件落点由本批 OpenSpec 固定，避免在 Agent 中各自复制一份逻辑。

快照至少包含：

| 类别 | 内容 |
|---|---|
| 目标与顺序 | 会话／片段 ID、完整语义顺序、相邻片段引用、来源产物版本 |
| 有效参数 | 选中模型及能力、请求模式与有效模式、最终时长、明确的适配转换 |
| 参考素材 | 有序资产 ID、用途、内容指纹、标签；短时签名 URL 只用于执行，不作为长期语义身份 |
| 内容约束 | 镜头正文、每镜时长、景别、项目风格、人物／场景权威事实 |
| 可追溯信息 | 模板／解析策略版本、语义输入指纹、必要的参数来源说明 |

- [ ] 复用现有媒体路径归一化和访问守卫，不在新解析器中绕过鉴权或暴露任意路径。
- [ ] 模式转换和模型时长限制在改写前解析；视频执行校验其仍然有效，变更时触发失效流程。
- [ ] Ref2VA 按实际有序参考集执行 grounding，校验允许的 `<Picture N>` 标签集合。
- [ ] H3 和视频请求快照中共享字段必须精确相等；不只断言字段非空。

验收：多角色／场景、重复图片、缺图、模型能力约束、会话时长覆盖、首尾帧转参考模式；对比改写输入与适配器最终请求，逐字段相等。

### B2｜统一实际提示词来源和失效规则（WF-04）

主要落点：`VideoStage.tsx`、`orchestrator.py`、H3／视频产物 schema 和实际请求选择逻辑。

- [ ] 按决策 Q1 保存人工有效正文及来源，不把 UI 描述与实际生成正文混用。
- [ ] H3 产物记录其输入指纹；正文、素材选择、模式、时长、风格或权威事实变化后，不能继续静默当作新鲜结果。
- [ ] 旧产物缺指纹时仍可展示，不自动认定新鲜；再次生成前明确要求重算或经用户确认使用现有正文。
- [ ] 改写页重新改写不得悄然覆盖视频页人工正文；清除人工覆盖或采用新改写由显式操作完成。
- [ ] 整阶段、单条、修订和 PATCH 共用有效性判定；后台结果按版本／归属检查，避免旧任务覆盖较新的编辑。
- [ ] 非目标条目、历史版本和已生成媒体保持可查看，不因失效标记被删除。

验收：先完成 H3，再在视频页修改并保存，捕获视频请求必须包含新正文；刷新仍一致。覆盖切换会话、修改分镜、切换模型／时长／参考图、后台改写完成和清除人工覆盖。

### B3｜完整上下文与目标集合分离（WF-06）

- [ ] 全部有序分镜用于计算邻接关系；目标 ID 仅决定本次要执行哪些条目。
- [ ] 全量、单条、非连续批量和用户修订采用同一邻接解析入口。
- [ ] 缺少下一帧、最后一片段及跨集边界沿用明确的既有契约；若需改变边界规则，单独在规格中列出。

验收：A、B、C 固定输入下，全量与单独处理 A 的有效模式和尾帧一致；处理 A、C 时 A 仍引用 B。非目标 B 不产生重写调用、不被覆盖；补最后一条和跨集用例。

## 六、阶段 C：正文语义与模板分型

### C1｜导入语义和中英文解析（WF-01／02）

主要落点：`script_import.py`、`storyboard_agent.py` 及剧本格式约束。

- [ ] 显式标注优先于正则，覆盖 `action/narration/scene_desc/dialogue`；结构行和空行有明确归类。
- [ ] 场景头、人物清单中英归一化，英文 `Characters:` 不进入对白单元。
- [ ] 保留源行／源区间到单元的可追溯关系，区分正文单元与非正文结构行；不能只统计已经识别出的 U 单元。
- [ ] 保持原文可还原、对白字面保真、顺序与场景边界，旁白不自动创建可见人物。

验收：纯旁白、普通动作、带标签动作、混合对白、中文／英文场志、同一场景重复进入、同名／别名人物；未消费正文必须被明确报告而非静默丢弃。

### C2｜共享语言和资产类型契约（WF-10、PR-02）

主要落点：生成／导入／续写的提取模板与 `script_agent.py`、资产生成／评估选路、首帧语言选路。

- [ ] 显式语言值用于初次生成、续写、修订、提取、首帧；旧会话统一推断一次，避免标题与正文语言冲突。
- [ ] 资产类型不靠自由文本描述临时猜测；初次／导入／续写输出同一结构，保留 `species` 的兼容语义。
- [ ] 人物模板关注身份／服饰，动物关注体态／毛色，产品关注结构／材质，标识关注轮廓／文字，建筑关注立面／空间关系。
- [ ] 生成与评估成对切换，非人物不得出现强制人体四视图或人体合格标准。
- [ ] 无类型的旧资产保持可读，不能未经确认批量重分类或重生图。

验收：人物、动物、产品、Logo、建筑固定样例横跨生成／导入／续写；捕获模板选路、字段与评估标准。实际画质提升另行批准真实模型对照，不以 mock 通过代替。

### C3｜统一 H3 规则与模板契约检查（PR-01）

- [ ] 以现行规格定义唯一的事实／修订优先级，同步 system、用户修订包装和校验器。
- [ ] 项目禁词与指南建议冲突时明确覆盖关系，保留来源原件和按模式选路。
- [ ] 增加模板变量完整性、关键规则一致性、中英 schema 对齐检查；解析失败不得被当作成功。
- [ ] 检查英文路径与实际可达性，不把“文件存在”当作支持证明。

验收：每种模式捕获实际发送的完整请求；检查只附带相关指南，规则不存在相反优先级，输出校验仍保留原定硬约束与三次上限。

## 七、阶段 D：成本、上下文和文档治理

推荐内部顺序：D1 观测 → D2 缓存 → D3 分集／并行 → D4 上下文预算。文档同步 D5 随各子批次完成，不等到最后才更新。

### D1｜建立可比较的调用观测（OP-05）

- [ ] 按阶段、模板版本和模型路由记录调用次数、耗时、校验重试、缓存命中与可用 token usage。
- [ ] 供应商未返回 token 时记录未知，不拿字符数伪装精确 token；费用仅在有可信价格和 usage 时计算。
- [ ] 区分文本、VLM、生图、视频成本，区分正常、修复和重试调用；不记录密钥、签名 URL 或无必要的完整用户正文。

验收：mock 响应带／不带 usage 都能表达真实状态，失败和重试计数准确；对照记录模板、模型、输入版本，避免不同条件混比。

### D2｜会话级 grounding 缓存（WF-12）

- [ ] 按决策 Q5 实现会话隔离、有界容量与淘汰；同内容不同模型／策略不能误命中。
- [ ] 缓存随会话清理，不能让过期授权或签名 URL 成为新的访问依据。
- [ ] 同轮并发对同键复用在途请求；失败结果最多在当次执行复用，后续显式重试可重新看图。
- [ ] 本轮不引入数据库迁移或新缓存服务；若现行规格要求超出进程生命周期，先调整方案并确认。

验收：同会话两次独立执行使用同图，成功 VLM 请求累计一次；改图、改模型、改策略后重新调用；不同用户／会话不互相泄漏，重启后的缓存行为按约定说明。

### D3｜确定性分集与受控评估并行（OP-01／02）

- [ ] 标题明确时优先代码分集，独立验证正文还原、集号和顺序；歧义才回退模型提取。
- [ ] 台词与情节评估在现有模型并发能力内并行，聚合顺序固定，失败／取消处理与当前停止契约一致。
- [ ] 不在本批同时合并两个评估维度、不改变 temperature 或扩大供应商并发配额。

验收：标准剧本少一次分集 LLM 调用且正文精确一致，歧义输入正常回退；并行仅主张关键路径收益，调用数不变，不能把减少等待描述为减少 token。

## 八、验收矩阵与环境约束

### 环境与权限

1. 后端单测、集成、E2E、冒烟、回归、脚本和测试性质的请求捕获全部在项目已有 Docker 测试／运行环境执行，不在宿主机运行。
2. 优先复用已有容器、镜像、Compose 与验证脚本；不得构建／重建基础镜像或临时另一套测试镜像，任何启动方式都不能隐式触发构建。
3. 必要时可在已有运行容器临时安装测试依赖，不固化镜像；若环境仍无法满足，先报告原因和方案，不绕过规则。
4. 如需改 Dockerfile、Compose、依赖、启动脚本或其他项目文件来运行测试，先形成方案并获得明确同意。
5. 前端静态检查优先使用项目已有命令，可在宿主机运行；涉及后端行为的验证仍遵守 Docker 边界。实施后的 UI 交互验收另行安排浏览器取证。
6. 固定数据、mock 模型和网络安全门优先；没有单独授权，不调用真实模型、不生成付费素材、不污染用户会话。
7. 测试从模块级延伸到 API／编排级，期望值来自独立夹具或契约，不复用被测 helper 自证；PASS 数按实际输出记录，不预填成功条数。

## 九、风险控制、回退与交付物

- **原文保真风险**：解析改造只改变内部解释，不覆盖上传原文；保留原路径和可还原验证。
- **旧产物兼容风险**：新增元数据应有显式缺省状态，不批量改写历史 JSON／数据库数据；需要迁移时另提方案。
- **编辑覆盖风险**：把用户选择、自动推荐和版本时序分开；发生冲突时保留用户数据，不采用最后一个异步结果无条件获胜。
- **画质回退风险**：模板和上下文策略分批变更，保留对照版本；不在同一实验同时改模型、参数和提示词。
- **成本回退风险**：缓存故障回退为有界原调用；评估失败不扩增生图；上下文预算未通过质量门槛则保留原策略。
- **范围风险**：本计划不授权部署或 Git 操作；若需要提交／上线，按用户后续明确授权另行执行。

每个已批准子批次的交付物：相应 OpenSpec 工件、范围内代码／模板改动、可在已有 Docker 环境复现的验证、请求／产物证据、修复状态更新及剩余缺口。UI 相关批次补充经批准的浏览器截图；真实模型对照单独记录模型、模板、输入和费用条件。

当前全部待办保持未完成。本次仅将审查与推荐实施顺序文档化，不宣称任何代码问题已修复或任何优化收益已验证。
