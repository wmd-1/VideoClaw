## 一、目标与非目标

### 目标

1. 用户修改的内容与实际提交模型的内容一致。
2. 上游正文、场景、资产选择和时长在阶段间不丢失、不被旧结果悄然覆盖。
3. H3 改写与视频执行使用相同的素材、顺序、模式和有效参数。
4. 人物／非人物、中英文、生成／导入／续写采用一致的内部契约。
5. 在不降低保真、可控性和历史恢复能力的前提下，减少重复请求与冗余上下文。
6. 区分“未评估”“相对最好”“绝对合格”，并使优化收益可测量。

### 非目标与保护边界

- 不引入新的 Agent 编排框架，不替换现有主工作流，不更换模型供应商或默认模型。
- 不在本轮接线修复中启用 `temperature` 透传；维持既有“当前未生效、预留”的语义。
- 不删除上传原文、历史视频／图片、人工选择和非目标条目；不通过清空产物解决失效问题。
- 不把旁白变成出镜人物，不把静态首帧模板与动态视频模板合并。
- 不取消分镜硬校验、H3 有界重试或 Doctor 错误分流；不以放宽校验制造通过率。
- 不改写官方指南来源副本，不凭无引用扫描直接删除兼容模板。
- 不预先承诺节省百分比；真实模型调用和费用需单独授权。
- 不自动提交、推送、归档 OpenSpec 或连续执行多个未经确认的 change。

## 三、实施前需确认的建议决策

以下是推荐方案，不表示用户已经拍板。确认后写入对应 OpenSpec；未确认前不执行。决策使用 Q1～Q7 编号，与阶段任务 A1～D5 区分。

| 决策 | 推荐方案 | 不建议直接采用的替代方案／原因 |
|---|---|---|
| Q1：实际提示词来源 | 视频页显式保存形成“人工有效正文”；无人工正文时使用新鲜 H3 结果，再按既有规则回退；前端展示实际提交正文及来源 | 只改 `description` 而保留隐藏覆盖；或取消 H3 优先级，破坏已有改写功能 |
| Q2：有效参数与失效 | **单一解析 + 可见 adjustment（2026-11-02 已实施）**：`core/video_params.resolve_effective_duration`——`会话覆盖 > 分镜时长 > 默认 8`，再按所选视频模型实际 `duration{min,max}` 夹取；H3 与视频同源；H3 的 4～15 硬编码已删除（回退区间与 `FALLBACK_RANGE` 共用）；夹取变化写入 `duration_adjustment`（H3 条目与视频产物均带），仅在能力区间非法时报错 | “差值>1 秒就报错”（阈值无依据）；或“仅会话覆盖为准”；或维持两处各自解析 |
| Q3：评估不可用 | 标为未评估／评估失败，可人工使用已有候选；相对选优不自动等于绝对合格，不填造分数 | 统一判通过，或评估异常就无界重生图 |
| Q4：语言与资产类型 | 语言显式保存，旧数据只在统一入口推断一次；资产类型由共享 schema 承载，生成与评估成对路由 | 每阶段按标题猜语言；只修改人物生成模板而不修改评估模板 |
| Q5：grounding 缓存 | 会话隔离、进程内有界缓存；缓存键含模型／策略与图片内容指纹；不在本轮承诺跨重启命中 | 无界进程全局字典、跨用户共享未经授权内容、为缓存另建基础设施 |
| Q6：连续性摘要预算 | 先计量，保留当前全历史摘要作为对照；通过独立规格与质量评估后再采用受限上下文 | 直接截断全部前序摘要，违反现行规格并丢失远距离连续性 |
| Q7：H3 规则冲突 | 按现行规格统一事实优先级；明确项目规则覆盖指南通用示例，保留指南原件和校验约束 | 删除校验以提高通过率，或擅自改变用户意见与权威事实优先级 |
| Q8：后台单条重生成的选中（**2026-11-02 实施时确定**） | 用户**显式**发起重生成 → 新选优结果成为 `selected`；但执行期间用户手改过（当前值 ≠ 执行开始时快照）则保留用户值；非目标条目保持原选中 | 只按“本次优先”：会反向覆盖执行期间的手选（本计划首版盲区，2026-11-02 已修补） |
| Q9：评估状态可观测（**2026-11-02 定稿 B，已实施**） | 落库**最小集**：`evaluated`／`eval_status`／`selection`／`score`（有则存）；`issues`/`suggestion` 原文一律不落。**继承**：本轮未生成/未评估的条目沿用已存 `evaluation`；本轮返回不可落库的失败标记（如 `{error_type, error}`）同样回退已存，全量空跑与单条失败都不得抹掉历史。**事件与产物同口径**：`asset_complete` 构造时即用 `_evaluation_payload` 收敛，否则原始文本会经工作层与运行中视图泄漏。**未知语义两分**：条目缺 `evaluated`（旧形态）→ `unknown`；条目根本没有 `evaluation` 键 → 未评估（不补键）。**scope 约束方式**：编排层按字段透传、不分 stage；本轮 `reference_generation` 不落库仅因其不发 `evaluation`，一旦该阶段 emit 就会自动扩大。前端展示另排期 | 把“全量空跑不抹历史”省掉；或在事件里直传原始 `eval_result`（文档写“不落”但工作层仍有）；或声称“scope 仅 character_design”却在编排层无任何限制 |

## 九、风险控制、回退与交付物

- **原文保真风险**：解析改造只改变内部解释，不覆盖上传原文；保留原路径和可还原验证。
- **旧产物兼容风险**：新增元数据应有显式缺省状态，不批量改写历史 JSON／数据库数据；需要迁移时另提方案。
- **编辑覆盖风险**：把用户选择、自动推荐和版本时序分开；发生冲突时保留用户数据，不采用最后一个异步结果无条件获胜。
- **画质回退风险**：模板和上下文策略分批变更，保留对照版本；不在同一实验同时改模型、参数和提示词。
- **成本回退风险**：缓存故障回退为有界原调用；评估失败不扩增生图；上下文预算未通过质量门槛则保留原策略。
- **范围风险**：本计划不授权部署或 Git 操作；若需要提交／上线，按用户后续明确授权另行执行。
- **重叠实施风险（2026-10-31 新增）**：`user-space-isolation` 仍在推进（截至复核时 82/101，第 13 组待复审、第 14–17 组未完成）。涉及消费计划、提交事务、发布映射、用户编辑保护的改动必须先核对该变更当前状态，能合并就合并，不平行实现两套语义。
