## 0. 一页结论

| 维度 | 决定 | 核心理由 |
|---|---|---|
| 身份模型 | **上游 GUIP 统一身份 + 单租户内按 `login_name` 字符串隔离**：无用户表 / 注册 / 密码 / JWT；`X-User-Login-Name` 头 + GUIP `globalInfo` 解析；`users.mode = guip \| single`（`guip` 为目标部署，`single` 仅兼容单机） | 对齐 Handoff；不引入账号体系，隔离键单一、可审计 |
| 隔离方式 | **PostgreSQL 元数据库**（`sessions` / `tasks` / `sandbox_records` / `saved_items` / `artifact_files` 带 `owner`；`session_stage_artifacts` 经 session 归属）+ 统一归属校验收口 + 媒体控制器 | 事务、索引、唯一约束；JSONB 存 stage 产物；参考平台同栈 |
| 元数据存储 | **PostgreSQL 16（唯一）**；SQLite fallback 已在 v6 移除 | 多用户/阶段检查点/空间查询需要事务与索引；允许重建镜像 |
| 中间产物 | **`session_stage_artifacts` 按 stage 入 DB**（剧本/角色/分镜/参考图/改写/视频/后期）；**每阶段完成一个检查点事务** | 恢复用户进度：最后 completed 的 payload 始终可用 |
| 二进制中间产物 | **新写入必须 MinIO**；local 只兼容未迁移旧文件 | 上传核验后同事务发布；新业务失败不生成正式 local fallback |
| 媒体隔离 | `MediaController` 替换 `/code/result` 静态挂载：校验 `?user_login=` 归属后从本地/MinIO **流式返回**（所有模式）；预签名只给推理服务 | `<img>/<video>` 无法带头；查询身份缺口所有模式接受 |
| 个人空间 | 新增 `/space`：按业务域聚合「已完成作品」，再加「我的收藏」；**派生视图，不建 space 表** | 对齐 Handoff 的「个人空间不是独立数据容器」；作品粒度按成片文件 |
| 收藏 | 收藏时把成片**复制**到 MinIO 收藏桶，元数据写 `saved_items` | 会话/任务删除后收藏仍可用；`UNIQUE(owner, work_id)` 保证幂等 |
| 旧数据 | 一次性 CLI **JSON → PostgreSQL、本地文件 → MinIO** 幂等导入；owner 缺失补 `legacy_owner`（默认 `local`） | 数据不丢；JSON/本地文件保留为备份；不阻塞启动 |
| 并发 | 多用户/多会话可同时运行；同一 session 同时只能跑一个阶段；**不做每用户并发/日配额**（已确认） | 单进程 ≠ 单用户单任务 |
| 本轮落地节奏 | 交接盘点 → 公共原语不启用 → 工作流完整切换 → Pipeline/Sandbox完整切换 → 联合验收 → 迁移契约收尾 | 详见§18与tasks第12–17组，每组结束交审 |

**一句话**：保留单进程（多用户可并发），用「上游 GUIP 头身份 + PostgreSQL `owner` 归属与阶段检查点 + MinIO 对象存储 + 媒体控制器」实现单租户多用户隔离与阶段级恢复；个人空间以成片聚合为主、收藏副本保证作品长期留存。

### 1.2 参考平台做法（Design_Agent_Platform）

- **身份链路**：前端 `authStore` 按 `?User=` > GUIP SDK 解析登录名，`api/client.ts` 统一注入 `X-User-Login-Name`；后端 `deps.get_guip_user_info` 缺失即 401，会话与收藏查询按 `Conversation.login_name` 过滤（全站统计另走管理员白名单；其 `overview/daily` 存在跨用户缺口，见 Handoff §9）。中文姓名/机构不走头（Headers 仅 ISO-8859-1），随创建会话 body 落库。
- **媒体与产物**：产物读取走带归属校验的接口；收藏时把文件深拷贝到**收藏专用桶**，会话删除/产物裁剪/桶归档都不影响已收藏作品。
- **个人空间**：`modules/space/SpacePage.tsx` 按能力域分 tab + `SavedTab`「我的收藏」；`/v1/users/me/artifact-counts` 一次请求预取全部 tab 徽标；收藏上限默认 50。
- **管理视角**：`/stats/all` 仅对 `admin_login_names` 白名单开放，白名单为空则默认拒绝。
- **浏览器约束的处理**：WS 握手与 `<img>/<video>/<a download>` 无法带自定义头，分别用 query 参数与只读 GET 降级；写接口仍强制走头。这是参考平台的降级方式，本方案**不照搬 query 身份**（见 §1.3、§6.5）。

### 1.4 关键约束

1. **单进程**：归属索引与缓存可以放内存，但**不得**破坏 `assert_single_process_premise`。
2. **源码与镜像**：后端代码经 compose 只读挂载，改代码用 `restart`；本方案新增 `psycopg`/`minio` 依赖，**允许重建后端镜像**（用户已同意）；不得为测试临时改镜像，但依赖变更属于正式实施。
3. **保留历史产物**：JSON → PostgreSQL、本地文件 → MinIO 是导入/上传，不移走/重写图片、视频与历史 JSON（作为备份）。
4. **后台线程**：Pipeline 任务、Video 生成在后台线程/线程池执行，拿不到请求上下文；归属必须在**创建时**写入元数据，不能依赖请求作用域。
5. **浏览器媒体请求**：`<img>/<video>/<a download>` 不能带头，前端媒体 URL 追加 `?user_login=`（同源，经 Next rewrite）。
6. **SSE 直连**：`lib/workflowApi.ts` 的流式请求直连后端端口（Next 会缓冲 SSE）。用户已接受浏览器直连；残余风险与可选加固见 §4.7。

### 1.5 与 Handoff 的对齐与取舍

Handoff 的核心模型是「上游 GUIP 统一身份 + 单租户内按 `login_name` 字符串隔离」，并明确列出自身缺口。本方案逐项处理：

| Handoff 结论 / 缺口 | 本方案 |
|---|---|
| 无用户表、注册、密码哈希、JWT/Session；身份来自上游 GUIP | **完全采用**；VideoClaw 不新增用户表 |
| `login_name` 是唯一隔离键；`user_name` / 机构仅展示与审计 | **采用**；会话/任务/沙盒只存 `owner`（login），姓名/机构不参与鉴权 |
| 单资源归属不匹配返回 404（不泄露存在性），身份缺失 401 | **采用**；统一经 `core/ownership.py` 断言 |
| 管理员是配置白名单（env / config），默认空 = 无人可读 | **采用**；`users.admin_logins`，`single` 模式 `local` 视为管理员 |
| 个人空间是派生视图，没有 `space` 表 / 成员 / 邀请 | **采用**；`/space` = 当前用户作品聚合 + 收藏副本 |
| 收藏 = 引用 + 转存；源会话删除不影响收藏 | **采用**；复制到 MinIO 收藏桶 |
| 前端身份只存内存、无身份不挂载应用 | **采用**；不做 localStorage / sessionStorage 缓存，无身份渲染 `IdentityMissing` |
| 缺口 #1：身份头完全由客户端自报 | **用户决策：允许浏览器直连/自报头（内网信任边界）**；`?User` 保留；可选 `trusted_proxy_cidrs`/nginx/token 加固（§4.7） |
| 缺口 #2：GET `?user_login=` 可冒读产物 | **所有模式保留**（用户决策）：仅媒体 GET 接受 query；浏览器改后端流式，推理服务仍预签名 |
| 缺口 #4：无统一 repository / RLS，漏写过滤即越权 | 改用 PostgreSQL + `db/repositories` 强制 owner 条件；`core/ownership.py` 只做断言与媒体路径映射；RLS 可后续 |
| 缺口 #5：产物键不含 login，路径本身不提供隔离 | MinIO 对象键统一带 `{owner_key}/`，媒体控制器按 `artifact_files` 校验归属 |
| WebSocket 握手用 query 传身份 | VideoClaw 用 SSE（`fetch` 可带头），**无此缺口** |
| 每用户并发 / 日配额 | **不做**（用户确认）；多用户/多会话可并发 |

### 1.6 「单进程」是什么（本次加 DB 的边界）

`api/app.py::assert_single_process_premise()` 在启动时检查 `WEB_CONCURRENCY` / `UVICORN_WORKERS` / `--workers`，大于 1 直接拒绝。它限制的是 **Uvicorn worker 进程数 = 1**，不是「同时只能一个请求」：一个进程内仍可 asyncio 并发处理很多请求。

必须单进程，是因为以下**活状态只在内存**：

- `WorkflowEngine.sessions`（全部会话状态）、`_stop_events`（停止信号）、`_active_sessions`（正在执行的会话）；
- `_background_tasks`（SSE 断开后继续跑的任务）；`_boot_id`（判断 running 是否本进程留下）；
- 沙盒 `SANDBOX_ACTIVE_TASKS`；SSE 进度通道。

**单进程 ≠ 单用户单任务**：不同用户、不同会话可以同时运行；`_active_sessions` 只阻止**同一个 session 同时跑两个阶段**；阶段内条目并发由 `enable_concurrency` / 模型并发上限控制。真正的瓶颈是模型额度、ffmpeg、CPU，而不是全局单任务锁。**不做每用户并发/日配额**（用户确认）。

多个 worker 是多个独立进程、各一份内存：同一会话的请求可能落到不同 worker，导致重复执行、停止信号收不到、SSE 进度收不到、后台任务丢失、JSON/DB 写入互相覆盖。

**加数据库/对象存储不会解除这个约束**：PostgreSQL 只能让元数据跨进程一致，MinIO 只能让对象共享；上述内存态仍需「DB 租约 + 外部进度/停止通道 + 任务队列 + 粘性路由」才能多进程，属于后续独立提案。本方案继续保留单进程断言。详见数据库子方案 §2。

## 2. 目标与非目标

### 目标

- **G1 身份可识别**：任何请求都能确定「当前用户」；`guip` 模式下缺失身份一律拒绝。
- **G2 数据默认隔离**：会话、Pipeline 任务、沙盒记录、收藏、配置等**元数据/API/写操作**按用户隔离；越权 API 返回 404。**媒体 GET 不是隔离资源**：`/code/result/...?user_login=` 只做自报身份归属比对，改参即可读他人媒体（产品决策，见 §17.5/R10）。
- **G3 个人空间**：用户能在一个页面看到自己跨业务域的全部已完成作品，支持预览、下载、收藏。
- **G4 收藏可长期留存**：源会话/任务删除后，已收藏作品仍可访问。
- **G5 单机兼容**：`users.mode=single` 时 API 语义与当前版本一致；旧数据用一次性 CLI 导入 PostgreSQL，本地文件迁移 MinIO（或保持 local），不在 startup 自动跑。
- **G6 可运维**：旧数据导入/归属、管理员、收藏上限均可配置；日志可追溯导入与归属。

### 非目标

- N1 账号密码 / 注册 / 找回密码 / JWT 登录体系（本期用可信头）。
- N2 按用户计费、限流、并发配额、模型额度（用户确认不做）。
- N3 多实例/多副本部署（仍受单进程前提限制）。
- N4 每用户物理目录分区（见 §5.3 的取舍）。
- N5 把临时工作台（沙盒）产物纳入个人空间（见 Q4）。
- N6 移动/重写历史 session/task 文件。
- N7 媒体文件级隔离：媒体 GET 只做 `?user_login=` 自报身份归属比对，**不是安全边界**；能访问 `/code/result` 且知道/猜到 login 即可读他人媒体（见 §17.5/R10）。

## 3. 总体方案

### 3.1 分层

```text
┌─────────────────────────────── 浏览器 ───────────────────────────────┐
│ 身份解析(GUIP / ?User= 联调) → API 头 + 媒体 query user_login      │
└───────────────┬──────────────────────────────────────────────────────┘
                │ Next rewrite 或 nginx 同源代理（/api/*、/code/*）
┌───────────────▼──────────────────────────────────────────────────────┐
│ FastAPI                                                              │
│  ① 身份中间件 + 依赖 get_current_user（single 固定 local；guip 缺失 401）│
│  ② 归属校验 ownership.assert_*（统一 404）                            │
│  ③ 业务路由（sessions / workflow / pipelines / sandbox / space / …）   │
│  ④ 媒体控制器 MediaController（query 归属 + 本地/MinIO 流式）           │
└───────────────┬──────────────────────────────────────────────────────┘
                │
┌───────────────▼──────────────────────────────────────────────────────┐
│ PostgreSQL：sessions / stage_artifacts / artifact_files / tasks / ... │
│ MinIO：视频/图片/音频对象；本地 workspace：ffmpeg 临时工作目录            │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.2 关键原则

1. **API 默认安全**：`guip` 模式下身份缺失 = 401；API 归属未知 = 404（fail-closed）。**媒体 GET 例外**：query 身份可伪造，媒体不构成安全边界。
2. **单一收口**：所有 SQL 只在 `backend/db/repositories/`；所有归属断言只经 `backend/core/ownership.py`，禁止在路由里各写一份比较逻辑。
3. **创建时定归属**：`owner` 在创建会话/任务/沙盒记录时写入 DB 行；后台任务不再需要身份。
4. **服务端注入**：`owner` 永远取自身份依赖，**不接受**请求体传入。
5. **前端路径保持兼容**：媒体走 `/code/result/...?user_login=<login>`，由 `MediaController` 查 `artifact_files` 后流式返回；预签名只给推理服务。
6. **DB 只存元数据**：新图片/视频必须发布 MinIO，本地只是工作文件/缓存；仅未迁移旧文件保留 local 读取。缺失按文件标记，执行失败不得自动发布 local 结果。
7. **阶段检查点**：每完成一个阶段，在一个事务里写 `session_stage_artifacts` + `sessions` + `artifact_files`；这是恢复的原子边界。

### 3.3 请求链路（guip 模式）

```text
首次加载
  浏览器 ──GET /api/identity/mode──▶ { mode: "guip", allow_url_user: true }
  浏览器 ──GUIP globalInfo / ?User=(仅联调)──▶ login=alice（只存内存）
  浏览器 ──GET /api/identity/me (X-User-Login-Name: alice)──▶ 200（不设 cookie）
后续业务请求
  浏览器 ──fetch(/api/... , X-User-Login-Name: alice)──▶ 身份依赖 → 归属校验 → 业务
媒体请求
  <video src="/code/result/video/123/x.mp4?user_login=alice"> ──query──▶ 媒体网关 → 归属校验 → 流式返回
推理服务
  sglang ──GET <MinIO 预签名 URL>──▶ MinIO 直接返回对象（不经浏览器媒体网关）
```

## 4. 身份模型（上游 GUIP + login_name 隔离）

整个部署是**一个租户**：没有 `tenant_id`、没有用户表、没有空间/成员表；`login_name` 是唯一隔离键，`owner` 字段存的就是这个字符串。

### 4.1 两种运行模式

| 模式 | 适用场景 | 前端 | 后端 | 数据归属 |
|---|---|---|---|---|
| `guip`（默认，目标部署） | 内网统一身份：门户 / GUIP 注入登录名 | 解析 GUIP / `?User=`（联调）、注入头、无身份不挂载 | 头缺失 / 空 → 401；所有读写按 owner 校验 | 按 `login_name` |
| `single`（兼容 / 单机） | 无 GUIP 的单机、本地开发、OSS 试用 | 不渲染身份 UI | 固定 `login="local"`，不校验头 | 全部归 `local` |

> **升级影响**：默认值改为 `guip` 后，没有 GUIP 的环境会进入「身份缺失」页（不挂载应用）。单机/本地部署需显式设置 `VC_USERS__MODE=single`；若更看重「升级零行为变化」，可在 Q1 中选择默认 `single`、生产显式设 `guip`。
> 模式由后端运行时下发（`GET /api/identity/mode`），前端不需要构建期变量（避免「端口/配置被烤进产物」类故障）。

### 4.2 身份来源优先级（guip）

1. URL `?User=xxx`：默认开启（用户决策：保留显式身份覆盖）；显式指定时优先于 GUIP，用于联调/指定身份。
2. GUIP SDK：`window.promise?.globalInfo()`（1.5s 超时）优先。
3. GUIP SDK：`window.globalInfo()` 同步兜底（要求 `userInfo` 非空）。
4. 都拿不到 → 渲染 `<IdentityMissing />`，**不挂载应用**。

**身份只存内存**：不做 localStorage / sessionStorage 缓存；刷新 / 重开标签页重新解析；启动时主动清理历史遗留键。这与 Handoff §2.6 一致，避免共享机器串号。
> `allow_url_user` 默认 `true`（用户明确要求不关闭）。它只是前端是否采纳 `?User=` 的开关；不能阻止直接自设 `X-User-Login-Name`。信任边界见 §4.7。

### 4.3 身份传递通道

| 通道 | 方式 | 说明 |
|---|---|---|
| 业务 API | `X-User-Login-Name` 头 | 值必须是 ASCII 登录名；中文姓名 / 机构名不进头 |
| SSE（现状直连后端端口；§4.7 方案 1 改为同源代理） | 同一请求头 | `fetch` 可带头；需 CORS `allow_headers` 覆盖（现为 `*`）；VideoClaw 无 WebSocket，不存在 Handoff 的 WS query 缺口 |
| 媒体（`img/video/a`） | `?user_login=`（仅媒体 GET，所有模式） | `MediaController` 校验 owner 后流式返回；API 仍用头；缺口 #2 所有模式接受 |
| 推理服务拉取参考图 | MinIO 预签名 URL（local/legacy 用 `file://`） | 短 TTL；不经 query / 头 |
| 管理接口 | 同上头 | 登录名命中 `users.admin_logins` 即管理员 |

> v12 起浏览器媒体不再使用 cookie；`?user_login=` 是显式接受的自报身份，所有模式都可能被改参冒读，网络 ACL/审计仅作缓解。

### 4.4 后端身份入口（中间件 + 依赖）

```python
# api/identity_middleware.py（拟）
@app.middleware("http")
async def user_identity_middleware(request, call_next):
    if request.url.path in ("/api/health",):
        return await call_next(request)
    request.state.user_login_name = request.headers.get("X-User-Login-Name", "").strip()
    response = await call_next(request)
    # v12: 不再下发 vc_user；浏览器媒体用 ?user_login=，API 仍用头
    return response
```

```python
# core/identity.py（拟）
async def get_current_user(request: Request) -> CurrentUser:
    login = getattr(request.state, "user_login_name", "")
    if settings.USERS_MODE == "guip":
        if not login:
            raise HTTPException(401, "身份缺失：请通过 X-User-Login-Name 头传递登录名")
        if not _trusted_source(request):
            raise HTTPException(401, "身份来源不受信任")
    else:
        login = "local"          # single：固定本地身份，忽略任何自报头
    is_admin = True if settings.USERS_MODE == "single" else login in _admin_logins()
    # owner_key 与 owner 同源：login.strip() 后派生，路径/对象键只用 owner_key
    return CurrentUser(login=login, owner_key=owner_key(login), is_admin=is_admin)
```

规则：

- `_trusted_source()`：`users.trusted_proxy_cidrs` 为空 → `True`；非空 → 校验 `request.client.host` 是否命中 CIDR。
- 所有业务路由**只通过依赖拿身份**，禁止在业务代码里直接读头；媒体网关是唯一例外（它拿不到依赖注入，见 §6.5）。
- `trusted_proxy_cidrs` 非空时，只在 `request.client.host` 命中 CIDR 时采信身份头，否则 401。
- `CurrentUser` 增加 `owner_key` 字段/属性（由 `login.strip()` 派生），与 DB `owner` 同源；路径/对象键只用 `owner_key`。
- `single` 模式下 `local` 视为管理员；`guip` 模式下管理员只来自 `admin_logins`（默认空 = 无人可读，对齐 Handoff §2.5）。
- 可选 `user_name` / `linked_org_name`：只在「创建会话」body 中携带（中文），仅展示与审计，**不参与鉴权**。
- `admin_logins` 在 YAML 中为列表，在 `.env` 中为逗号分隔字符串；配置层统一解析为列表。
- **`login` 做身份格式校验，不直接进路径**：允许 `[A-Za-z0-9_.@-]`（非空、长度 ≤128、拒绝 `.`/`..`/分隔符）；**`owner_key = sha256(login.strip().encode('utf-8')).hexdigest()[:16]`**（DB 仍存原 login；保留大小写、区分大小写）。这样 GUIP 的 `zhang.san@corp.com` 等登录名不需要改名，也不会有保留名冲突。P0-0 先采样真实登录名确认编码。

### 4.5 身份接口（新增）

| 方法 | 路径 | 行为 |
|---|---|---|
| `GET` | `/api/identity/mode` | 公开；返回 `{"mode":"guip\|single","allow_url_user":true}`（前端引导用，避免用 401 判别模式） |

- v12 不再设置媒体 cookie；前端媒体 URL 自行追加 `user_login`。

#### 管理员怎么定义

管理员**不是预置账号/密码，也不是 users 表**；它是 **`login_name` 白名单**，只影响「能否写全局配置 / 看全站统计」，身份仍由 GUIP（或 `?User`）提供：

- `.env`（推荐，环境相关）：`VC_USERS__ADMIN_LOGINS=alice,bob`
- `config.yaml`：`users.admin_logins: [alice, bob]`
- 优先级：进程环境 > `.env` > `config.yaml` > 默认值；两者都为空 = **无人是管理员**。
- `single` 模式：`local` 自动视为管理员。
- 普通用户：业务功能正常，但 `PUT /api/config`、`POST /api/models/test`、设置页保存返回 403；设置页只读。
- 改 `.env` 需 `up -d backend` 重建容器；改 `config.yaml` 必须 `restart backend`；设置页保存即时写入内存/文件。
- 如果以后需要“独立管理员账号”，那是完整账号体系（B3），不在本期。

### 4.7 信任边界（用户决策：允许浏览器直连）

- **决策**：浏览器直接访问后端/SSE 没问题；GUIP 只做身份区分；**`?User` 保持开启**；不强制 nginx 反代、不加签名 token。
- 身份头是**信任输入**，不是认证；上游 GUIP（前端 SDK）/ `?User` 提供身份声明，本系统只做「这条数据是不是你的」归属校验（对齐 Handoff §2.4）。
- 残余风险：能访问后端端口的人可以自设 `X-User-Login-Name` 冒充他人；这是内网信任边界的已知缺口，需靠网络隔离/审计约束，不在本期用签名解决。
- 可选加固（不默认）：nginx 流式反代 + `trusted_proxy_cidrs`；或后续签名 token。启用时按方案调整 `DIRECT_API_BASE`，并保证 SSE 也走该代理（否则直连会被 401）；不改变本期默认。
- `allow_url_user: true`（用户明确保留）；`?User` 优先级高于 GUIP，用于显式身份覆盖；用户区显示「调试身份」角标。
- **审计**：每次请求记录 `login`（API 头 / 媒体 query）、IP、路径、结果码；**不承诺区分** `?User`/GUIP（后端无法区分）。共享链接误用风险写入部署说明。
- `?user_login=` 是自报身份；所有模式接受冒读缺口，网络 ACL/审计仅作缓解。
- API 越权统一 **404**；缺身份 401；已确认身份但无权限（管理员接口）403。**媒体 GET 例外**：改 `user_login` 可读他人媒体（已接受，见 §17.5/R10）。`trusted_proxy_cidrs`/nginx 只保护 API/网络，**不保护媒体 query**。
- **媒体 GET 接受 `?user_login=`**（Handoff 缺口 #2，所有模式风险已接受）；API 仍不采用 query 身份；`?User` 只是前端身份来源，API 仍通过头传递。
- `GET /api/config` 的 API Key 脱敏、`PUT /api/config` 的管理员门槛是本期安全边界的一部分（见 §6.4）。

## 5. 数据归属与持久化

### 5.1 归属字段

元数据主存储在 PostgreSQL，二进制在 MinIO（表结构、SQL、repository 接口见[数据库子方案](./用户与个人空间-数据库方案.md) §5–§6）：

| 数据 | 载体 | 归属字段 | 写入时机 | 旧数据 |
|---|---|---|---|---|
| 主流程会话 | `sessions` 表（`session_id` PK） | `owner NOT NULL` | `create_session` / `save_session_to_disk` | JSON 导入；缺失 → `legacy_owner` |
| 中间产物（剧本/角色/分镜/参考图/改写/视频/后期） | `session_stage_artifacts` 表（`(session_id, stage)` PK，`payload_json`） | 通过 `sessions.owner` 间接归属 | `save_session_to_disk`（按 stage upsert） | 旧 `artifacts` 拆到每个 stage 一行 |
| 二进制中间产物（图片/视频/音频） | `artifact_files` 表（`owner`、`session_id`/`task_id`、`storage_kind`/`bucket`/`object_key`/`public_path`/`local_path`/`missing_at`） | `owner NOT NULL` | 上传 MinIO 后随检查点写入 | 从旧 artifacts/文件扫描导入 |
| Pipeline 任务 | `pipeline_tasks` 表（`task_id` PK） | `owner NOT NULL` | `create_task` / `save_task` | JSON 导入；缺失 → `legacy_owner` |
| 沙盒历史 | `sandbox_records` 表 + `sandbox_paths` 路径表 | `owner NOT NULL` | `SandboxRepo.insert` | `history.json` 导入 |
| 沙盒活动任务 | 进程内 `SANDBOX_ACTIVE_TASKS` | `owner`（内存） | `_start_active_task` | 不适用（进程重启即清） |
| 收藏 | `saved_items` 表 + MinIO 收藏桶 | `owner NOT NULL`；`UNIQUE(owner, work_id)` | 收藏时 | 不适用 |

`owner` 的值就是上游 `login_name` 字符串（不是用户 ID，也**不建 users 表**）。姓名/机构如需展示，可在 `sessions` 行冗余 `owner_name` / `owner_org`，仅展示与审计，不参与鉴权。`meta` 仍是生成参数集合，不塞 owner。

### 5.2 存储布局

元数据在 PostgreSQL，二进制在 MinIO，ffmpeg 用本地临时工作目录：

```text
宿主机：
├── data/postgres/                 # compose volume：PostgreSQL
├── data/minio/                    # compose volume：MinIO
└── video-claw/video-claw/backend/
    ├── code/
    │   ├── data/sessions/*.json   # 仅旧数据导入（不再双写）
    │   ├── data/tasks/*.json      # 仅旧数据导入
    │   ├── work/_refs/<owner_key>/  # ensure_local 缓存（只由 resolver 写，用户不可提交）

    │   └── result/**              # 旧数据 / local fallback（非默认）
    └── temp/users/<owner_key>/…   # 上传文档按用户分目录

  videoclaw/{owner_key}/{sid}/{stage}/{execution_id}/{filename}
  videoclaw/{owner_key}/{task_id}/{filename}
  videoclaw/sandbox/{owner_key}/{record_id}/{filename}
  videoclaw-saved/{owner_key}/{item_id}.{ext}
```

- `artifact_files.public_path` **规范形态为 `/code/result/...`**；`core/media_refs.to_public()` 把 `/code/result/...`、`result/...`、`code/result/...`、`/app/code/result/...` 归一成它；`MediaController` 查 DB 后从本地/MinIO 流式返回。
- 收藏元数据在 `saved_items`；收藏副本在 MinIO 收藏桶（不设 ILM）。
- 路径/对象键中的 `<login>` **均指 `owner_key = sha256(login.strip().encode('utf-8')).hexdigest()[:16]`**，DB `owner` 仍存原 login；保留大小写、区分大小写。
- `storage_kind=local` 仅用于**未迁移旧文件读取**，不作为新写入/部署模式。

### 5.3 为什么不做产物物理目录分区

| 方案 | 代价 | 结论 |
|---|---|---|
| 每用户物理分区（`result/users/<login>/…`） | 需要把 `login` 贯穿 `orchestrator` → `pipelines` → `models/*` 的每一处路径构造；后台线程无请求上下文，需改造调度与上下文传递；历史文件要迁移；media_paths 白名单、清理逻辑、`media_ref_base_url` 拼接全部受影响 | 收益（文件系统级隔离）与改动面不成比例，本期不做 |
| PostgreSQL + MinIO + MediaController | DB 提供事务/索引/检查点；对象层提供共享与预签名 | **采用** |
| 仅前端过滤 | 无任何安全性 | 拒绝 |

> Handoff 的建议是「资源路径带归属前缀，不要只靠 UUID 不可猜」（其自身产物键未做到，列为缺口 #5）。本方案的对象键统一带 `{owner_key}/` 前缀，且媒体控制器按 `artifact_files.public_path` 校验归属；双保险。

### 5.4 归属解析单一收口

新增 `backend/core/ownership.py`，内部只调 DB repository（带内存缓存）：

```python
def owner_of_session(sid: str) -> str | None: ...        # SessionRepo.owner_of

def owner_of_task(task_id: str) -> str | None: ...        # TaskRepo.owner_of

def owner_of_sandbox_path(rel_path: str) -> str | None: ...  # sandbox_paths

def owner_of_file(public_path: str) -> str | None: ...     # artifact_files.public_path → owner

def owner_of_media(rel_path: str) -> str | None: ...     # 先查 artifact_files，再回退规则表

def assert_session_owner(sid: str, user: str) -> None: ...   # 不匹配抛 404

def assert_task_owner(task_id: str, user: str) -> None: ...
```

实现约束：

- 归属查询走 repository；`owner` 结果放进程内 LRU/字典缓存，新增/删除时失效；DB 是权威源，缓存只用于媒体高频请求。
- **MinIO 模式先查 `artifact_files.public_path`**；下表仅用于旧数据/local fallback。
- 沙盒：新对象键 `sandbox/{owner_key}/...` 直接按前缀判定；旧产物查 `sandbox_paths`；未命中 → `legacy_owner`。
- 媒体路径规则表（legacy/local fallback）：

| 顺序 | 相对路径（相对 `code/`） | 归属来源 |
|---|---|---|
| 1 | `result/script/<sid>.json` | `owner_of_session(sid)` |
| 2 | `result/image/custom/<sid>/**` | `owner_of_session(sid)`；**必须先于第 3 条**，否则 `custom` 会被当成 sid |
| 3 | `result/image/<sid>/**` | `owner_of_session(sid)` |
| 4 | `result/video/test_client/**` | 系统路径；一律 404（不属于个人资产，排查走容器内直接访问） |
| 5 | `result/video/<sid>/**` | `owner_of_session(sid)` |
| 6 | `result/task/<task_id>/**` | `owner_of_task(task_id)` |
| 7 | `result/sandbox/history.json` | 系统元数据；404（不得按 `<login>` 解析） |
| 8 | `result/sandbox/{images,videos,uploads}/**`（旧） | 沙盒路径索引；未命中 → `legacy_owner` |
| 9 | `result/sandbox/<login>/**`（legacy/local） | 路径中的原 `login`；**必须在第 8 条之后** |
| 10 | `result/saved/<login>/**`（legacy/fallback，不再新建） | 路径中的原 `login` |
| 11 | 其他 | `guip` 模式 fail-closed；`single` 模式放行 |

- 未知/无法解析的路径在 `guip` 模式返回 **404**；`single` 模式保持当前行为（放行），保证零破坏。

### 5.5 旧数据迁移与回滚

**迁移**：用一次性 CLI（详见数据库子方案 §10）：

```bash
docker compose run --rm backend python -m db.legacy_import --fallback-owner alice --dry-run
docker compose run --rm backend python -m db.legacy_import --fallback-owner alice --files  # 只处理 alice 名下文件
# 全量上传需管理员二次确认：--all-files（不要与 --fallback-owner 混用）
# 显式改属主（仅确认全量认领时使用）
docker compose run --rm backend python -m db.legacy_import --reassign-from local --to alice --dry-run
```

1. 先由 `init_db` 建表/迁移（`schema_meta.schema_version`）；**不在 startup 批量导入**（避免 healthcheck 超时）；
2. CLI 遍历 `code/data/sessions/*.json`、`code/data/tasks/*.json`、`result/sandbox/history.json`；
3. 逐条 `INSERT ... ON CONFLICT DO NOTHING`；`owner = 原值 or users.legacy_owner`（默认 `local`）；`artifacts` 按 stage 拆行；沙盒路径写入 `sandbox_paths`；
4. 本地 `code/result/**` 批量上传 MinIO，写 `artifact_files`；未迁移的保持 local；
5. 标记 `legacy_import_done=1`，记录计数；**不删除 JSON/本地文件**，作为备份。

**回滚**：停后端 → `pg_restore` 恢复 DB + MinIO 卷/`mc mirror` 恢复对象 → 回退代码；JSON/本地文件仍在，作为最后兜底。

**过滤口径（必须统一）**：DB `owner NOT NULL` 在导入时保证；`single` 模式只把**身份**固定为 `local`，查询仍 `owner='local'`，**禁止 `owner=None` 逃逸**；旧数据 `legacy_owner=local` 自然可见。

**注意**：建表在 `app.lifespan` 执行；**旧数据导入是一次性 CLI，不在 startup 跑**；多实例部署不受支持（与现有前提一致），文档需在 README 部署节注明。

### 6.5 媒体访问与 MinIO

#### 6.5.1 目标

前端 URL 继续使用 `/code/result/...?user_login=<login>`。`MediaController` 先校验 query 归属，再从本地/MinIO **流式返回**；浏览器不再 302 到 MinIO，也不依赖 cookie。

#### 6.5.2 判定顺序

`MediaController`：

1. URL 路径参数必须是 public_path 相对形态：先剥离 `/code` 前缀再 `posixpath.normpath` 映射到 `RESULT_DIR`；**含绝对路径/`..`/越出 → 404**。
2. 系统路径（`result/video/test_client/**`、`result/sandbox/history.json`）→ 404。
3. 取 `?user_login=`（所有模式强制），`safe_login` 校验；缺失/非法 → 401。
4. `artifact_files.public_path` 命中：login 与行 `owner` 比对；不一致 → 404（`single` 也用 `local` 比对）。
5. 未命中：回退旧路径规则表（§5.4）查 owner；仍未知 → 404（fail-closed）。
6. MinIO：`get_object` + Range 流式转发（在 `run_in_threadpool` 打开对象流，`StreamingResponse` 迭代；不阻塞事件循环）；对象缺失 → 404 并写 `artifact_files.missing_at`，**不得改写当前 stage status 或清除最后 completed 快照**。
7. 本地 fallback：`FileResponse`/Range；不经过任何 query 签名。
8. DB/MinIO 异常 → **404**，不降级为放行。

流式契约：

- `Range: bytes=` → **206** + `Content-Range` + `Accept-Ranges: bytes` + `Content-Length`；非法 Range → **416**；HEAD 只返回头、无 body；本地 `FileResponse` 可直接处理，MinIO 分支必须手写。
- MinIO：`get_object` 在 `run_in_threadpool` 打开，读取用 `iterate_in_threadpool`（或 Starlette 对 sync iterator 的包装）；`try/finally` 关闭并 release；客户端断开时取消，避免连接泄漏。
- `Content-Disposition` 默认 `inline`；仅 `?download=1` 时 `attachment`，不要一律 attachment（会让 `<video>` 变下载）。
- 响应头：`Cache-Control: private, no-store`、`Referrer-Policy: no-referrer`；访问日志脱敏 `user_login`；R10 的“URL 不进日志”必须由代码保证，不能只写在文档里。
- 容量：所有媒体字节经后端单进程转发（MinIO→后端→浏览器），比 302 多一跳；已补有界并发流（默认 8，超时 503+Retry-After）、256KB 分块、协程级单流硬超时（默认 300s；慢 `send` 严格，阻塞 `read` 受存储层读超时约束，MinIO 读超时仍待补）、断开/失败/吞吐/排队指标（`/api/health.media_streams`）；真实并发压测/断线取证仍待验；后续可评估 [nginx X-Accel-Redirect](用户空间-R15-nginx-X-Accel-Redirect方案-2026-11-10.md)。

#### 6.5.3 预签名（仅推理）

- 浏览器媒体不再使用预签名；`MediaController` 流式返回。
- 推理服务：用**绑定 `storage.public_endpoint` 的第二个 client** 调 `presigned_url`（SigV4 含 Host），TTL 1h；`custom_video._reference_uris`/`vlm_client` 只消费 `reference_urls`，禁止拼 `_refs` 本地路径。
- v13 删除 `mt`/`media_token`/`media_secret`/`media_token_ttl`；历史 `?mt=` 链接不再支持。
- `saved_items`/`artifact_files` 只存对象键，不存临时签名。

#### 6.5.4 兼容与迁移

- 旧 `/code/result/...` 书签：迁移后 `artifact_files.public_path` 可命中；未迁移的文件走 local fallback。
- **旧 `?mt=` 链接**：v13 起不再支持，返回 401/404；上线说明需注明“重新从页面打开”。
- **旧裸 `/code/...` 链接**：媒体 query 强制后，`single` 也会 401；同样需重新从页面打开。
- `media_ref_base_url` 仅对 legacy `file://` 生效；MinIO 推理用预签名，浏览器用 query + 流式。
- `.env.example` 的 `VC_MEDIA_REF_BASE_URL` 注释同步改为“仅 legacy file://，预签名不走它”。
- 对象缺失：媒体 404；列表/空间跳过或标 `stale`，提示重新生成。

## 7. 个人空间设计

### 7.1 信息架构

```text
个人空间 /space
├── 页头：标题 + 统计（项目数 / 作品数 / 收藏数）
├── Tabs：全部作品 | 主流程 | 文艺短视频 | 动作迁移 | 数字人口播 | 我的收藏
├── 作品网格（分页，默认 24/页）
│   └── 卡片：封面（视频首帧/图片） + 标题 + 域标签 + 完成时间 + 收藏/预览/下载
└── 预览弹窗：<video controls> 或 <img>；底部下载/关闭
```

**个人空间不是独立数据容器**：没有 `space` 表、`space_id`、成员或邀请；数据来源是当前用户的会话 + Pipeline 任务 + 收藏副本（对齐 Handoff §4.1）。

与参考平台的差异：参考平台 tab 来自 AgentRegistry 的能力域；VideoClaw 的能力域是**主流程 + 三条 Pipeline**，因此 tab 为固定业务域。不做「按会话历史」tab（首页已有「历史记录」，避免重复）；个人空间只收**已完成作品**。

### 7.2 「作品」口径（必须唯一）

| 来源 | 判定 | 标题 | work_id |
|---|---|---|---|
| 主流程 | `session_stage_artifacts` 中 `stage='post_production'` 的 `final_videos[]` 每个元素（`path` 非空且文件存在）；旧会话回退 `final_video` 视为第 1 集 | 剧本标题 + `name`（第 N 集） | `session:<sid>:ep:<episode>` |
| 文艺短视频 / 动作迁移 / 数字人口播 | 任务 `status == "completed"` 且 `artifacts[]` 存在 `kind=="video" && name=="final"` | 任务输入标题（`output.title` 优先，回退 `input.*`，与 `AppShell::taskTitle` 同口径） | `task:<task_id>` |
| 沙盒 | 不纳入（Q4） | — | — |

> 首版只收「成片」；参考图、分镜、剧本属于过程资产，后续可按域增加 tab。
> 一个会话可能产出多集成片 → 多张卡片；这是「作品」而非「项目」的自然粒度。首页「历史记录」仍是项目粒度。
> `created_at` 取 `sessions.created_at`；`completed_at` 取 `post_production` 检查点的 `completed_at`（缺失回退 `updated_at`）。

```http
// source_deleted = 源会话/任务已被删除（收藏副本仍在，仍可播放/下载）
```

实现要点：

- 用 `SessionRepo.list(owner)` + `TaskRepo.list(owner)` 查询 DB（不扫文件）；会话成片读 `StageArtifactRepo.get(sid, "post_production")`，按 §7.2 提取。`single` 模式传 `owner='local'`（禁止 None），`guip` 模式按当前 login 过滤。
- 媒体 URL 统一取 `artifact_files.public_path`（`/code/result/...`）；stage payload、`pipeline_tasks.artifacts_json`、`sandbox_records.output_json` 写入前都 `to_public`，读取时再幂等转换；不再把容器绝对路径返回给前端。
- 两个来源取全量后在 Python 合并排序，再按 `limit/offset` 分页（数据量数百）；`total` 用于前端分页。
- `saved` 标记用 `SavedRepo.by_work(owner, work_id)`（见 §7.4）。
- 越权：列表类只返回当前 owner 的数据；不存在/他人 → 空列表（不返回 404），避免探测。`POST/DELETE /api/space/saved` 属单资源操作，他人/不存在的 `work_id` 一律 404。

### 7.4 收藏（转存）

**目标**：会话/任务删除、产物清理后收藏仍可访问。

**存储**：

- 元数据：`saved_items` 表（`owner` + `work_id` 唯一）；
- 副本：MinIO 收藏桶 `videoclaw-saved/{owner_key}/{item_id}.{ext}`（不设 ILM）。

`saved_items` 行示例：

```json
{
  "item_id": "sv_<uuid4>",
  "owner": "alice",
  "work_id": "session:1778810088325:ep:1",
  "domain": "main",
  "title": "乡村教师 · 第 1 集",
  "source_bucket": "videoclaw",
  "source_key": "{owner_key}/1778810088325/post_production/1778810088325_ep1.mp4",
  "bucket": "videoclaw-saved",
  "object_key": "{owner_key}/sv_<uuid4>.mp4",
  "size_bytes": 12345678,
  "saved_at": 1778813000000
}
```

**流程**：

1. 解析 `work_id` → 源对象（必须属于当前用户；`artifact_files`/stage payload 指向的对象键）。
2. `SavedRepo.by_work(owner, work_id)` 已存在 → 直接返回现状（幂等，不重复复制）。
3. 每用户 `asyncio.Lock` 串行化「计数 → 复制 → 落库」。
4. 超限（默认 50）→ 409 `saved_limit_exceeded`。
5. MinIO 服务端 `copy_object` 到收藏桶（同 region 不落本地）；本地 fallback 时才复制文件。
6. `INSERT INTO saved_items`（`UNIQUE(owner, work_id)` 兜底并发）；插入失败则删除收藏桶副本。
7. 取消收藏：删收藏桶对象 + `DELETE saved_items`；幂等。
8. 列表：查 `saved_items`，`stat_object` 校验副本存在（缺失则跳过或标记不可用）；`source_deleted` 表示源会话/任务已删除，与副本是否存在无关。

**收藏媒体（saved-media）**：

- 新增 `GET /api/space/saved/{saved_id}/media?user_login=<login>`；按 `saved_items.item_id + owner` 查行，owner 不匹配 → 404。
- **不注入 `get_current_user`**：saved-media 是媒体通道，只解析 query；注册在 `space` 的鉴权 router 之外（或路由级覆盖依赖）。附录 A 已把该路由从 `/api/space/**` 必需头中拆出。
- 可选后续：将 saved-media 改挂 `/code/saved/...`，避免与 `space` 鉴权 router 混在一起；本期不阻塞。浏览器 `<video>/<img>` 不带 `X-User-Login-Name`，否则必 401。
- 从收藏桶 `bucket/object_key` 流式返回（Range/HEAD，与 §6.5 同一契约）；**不查 `artifact_files`**。
- `GET /api/space/saved` 每项的 `media.url` 返回**不带 `user_login` 的相对路径**；前端 `savedMediaUrl(saved_id, {download?})` 追加 query，避免登录名进入列表 JSON/缓存。
- `saved_id` 用 uuid4/128 bit（如 `sv_<uuid4>`）；在 query 身份可伪造前提下，加限流 + 审计；不要用 32-bit 短 id 作为唯一媒体句柄。
- 前端 `SavedTab` 使用 `savedMediaUrl(saved_id, {download:true})` 处理下载；不走 `mediaUrl()`。
- **A27**：带 `X-User-Login-Name` 完成 `POST /api/space/saved` 与删除源会话；随后**不带任何头、仅 `?user_login=`** 请求 `saved/{id}/media`，断言 200/Range 206；owner 不匹配 404；源 `public_path` 404。

**与参考平台的对应关系**：参考平台「收藏专用桶 + `saved_at/saved_storage_key` 列」→ 本方案「`saved_items` 行 + MinIO 收藏桶副本」；语义相同，均保证源删除不影响收藏。

## 11. 风险与备选

### 11.1 风险

| 编号 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 头身份可伪造（SSE 直连使后端端口可被浏览器访问） | 任意访问者可冒充 | **所有模式接受自报头风险**；可选 nginx/CIDR/token 加固（§4.7）；审计日志 |
| R2 | 媒体路径/对象键遗漏（新增产物类型） | 越权读取或误 404 | 新产物必须写 `artifact_files`；`MediaController` fail-closed；legacy/local 走规则表；A5/A6 覆盖 |
| R3 | 全局配置越权 | API Key / DB DSN / MinIO Secret 泄露、配置被改写 | 管理员门槛 + 密钥脱敏（含 `database.dsn`/`storage.secret_key`）+ 非管理员只读 |
| R4 | 收藏复制大文件 | MinIO 存储增长 | 默认上限 50 + 单文件大小上限（建议 2 GB）+ 收藏桶生命周期/管理员清理 |
| R5 | 旧数据导入/归属错误 | 用户看不到历史 | `legacy_owner` 可配置；导入日志；必要时提供一次性改属主脚本（P3） |
| R6 | SSE 直连跨域带 header 失败 | 工作流无法实时 | CORS 已 `allow_headers=["*"]`；验证 A1/A2 覆盖直连场景 |
| R7 | 单进程假设被打破 | 内存态/DB 写入不一致，重复执行 | 保持启动断言；DB 不解此问题；多实例需租约/队列/粘性路由（§1.6） |
| R8 | `cleanup_orphan_results` 误删 | 删掉他人/未导入数据 | 管理员专属；`SessionRepo.ids() ∪ 旧 JSON ids`；先 dry-run |
| R9 | 上传文件被跨用户引用 | 数据泄露 | 上传目录用 `owner_key` + 文件名随机串；不拼接原始 login；媒体入参仍走既有白名单 |
| R10 | `?user_login=` 可被改参冒读（所有模式） | 任意访问者可读他人媒体 | 用户已接受；网络 ACL 缓解；访问日志脱敏 `user_login`；query 仍会出现在 DOM/浏览器历史，无法避免 |
| R11 | 模型连通性测试被滥用 | 产生费用 / 探测内网 | `guip` 模式仅管理员；`single` 保持现状 |
| R12 | DB 与对象存储不一致 | 行存在但对象缺失/反之 | 先上传对象再事务；`stat_object` 校验；孤儿对象定期清理；子方案 S1 |
| R13 | PostgreSQL/MinIO 服务不可用 | 请求失败、启动失败 | compose 健康检查 + 启动失败即报；pg_dump/mc mirror 备份；连接池上限 |
| R14 | ffmpeg 与对象存储的本地文件依赖 | 处理链中断 | 下载到 `code/work/<sid>`，处理完上传并清理 |
| R15 | 浏览器媒体全部经后端流式转发 | 单进程带宽/连接压力，视频并发卡顿 | 已限制并发流（默认 8，按 event loop 独立；单 uvicorn loop 即进程上限）/分块/协程级单流 300s 硬超时（阻塞 `read` 的强制中断依赖存储读超时，MinIO 读超时仍待补），满载 503+Retry-After；健康接口暴露 `media_streams`（active/queued/bytes_per_second_avg/disconnected/partial/timed_out 等；`bytes_per_second_avg` 为进程启动以来平均，不作瞬时告警）；真实并发/断线压测待验；后续可评估 [nginx X-Accel-Redirect](用户空间-R15-nginx-X-Accel-Redirect方案-2026-11-10.md) |
| R16 | 依赖/镜像重建风险 | 构建失败/版本不兼容 | `psycopg`/`minio` 锁定版本；单独提交 pyproject/uv.lock；重建后在 Docker 内回归 |

### 11.2 备选方案

| 方案 | 代价/风险 | 结论 |
|---|---|---|
| B1 每用户物理目录分区 | 改动贯穿 orchestrator/pipelines/models；后台线程上下文；历史迁移；清理逻辑 | 本期不做，列为后续强化 |

## 17. 评审修订（入站归属与缓存，现行 v17）

> 本节保留 v17 的身份、路径与媒体基础约束；2026-10-30 核心发布/工作视图/恢复/清理的补正见§18，相关技术细节同步至 OpenSpec design D11–D19。

### 17.1 入站路径契约（P0）

拆成两个函数，职责不混：

- **`canonicalize(value, user, purpose) -> ResolvedMedia(str)`**：归属校验后返回 **public_path / 远程 URL / `users/<owner_key>/...`**；**持久化端点只用它**，绝不返回 `_refs`。
- **`materialize(value, user) -> ResolvedMedia(str)`**：public → `ensure_local` 返回本地缓存；temp → `TEMP_DIR` 本地路径；remote 原样返回。**只给消费点**。
- `ResolvedMedia` 是 `str` 子类，带 `trusted=True`、`public_path`、`local_path`；`guard_media_input` 检测到 trusted 时**跳过用户入参白名单**，raw `str` 仍走白名单。resolved 路径不得二次走白名单。

分支：

1. **远程形态**：`http://`/`https://`/`oss://`/`data:` 原样返回，不下载；保留现有 `REMOTE_MEDIA_PREFIXES` 能力（P18）。`file://` 解析为本地绝对路径后走第 3 支。
2. **规范 public**：`/code/result/...` → `artifact_files` 查 owner；不匹配 **404 且不下载**；命中后 canonicalize 返回 public，materialize 才 `to_local`。未命中回退 `ownership.owner_of_media` + owner 比对；仍未知 → 404，提示先跑 `legacy_import --files`。
3. **绝对路径**：`realpath` 后在 `RESULT_DIR` 下 → 转相对 → 走第 2 支；在 `TEMP_DIR` 下 → 必须落在 `users/<当前 owner_key>/`，否则 404；其他绝对路径 → 404。
4. **临时相对路径**：`users/<owner_key>/...` 断言段与 `user.owner_key` 一致，否则 400/404。
5. **其他相对路径**：归一后若落在 `RESULT_DIR` → 必须走第 2 支的 public/owner 断言；否则 404（fail-closed）。

端点差异：

- **持久化**：`PATCH artifact` 的 `selected`、`execute`/`intervene` body、pipelines `input_json`、sandbox records 用 `canonicalize` 写回原值；DB/GET 不出现 `_refs`。
- **消费**：`copy_input_file`、agent 读图、ffmpeg 用 `materialize`；`copy_input_file` 不再二次调 `guard_media_input` 的用户白名单；`sandbox._resolve_media_reference_url` 对 `ResolvedMedia` 不再调 `resolve_within_allowed_dirs`。
- `_guard_pipeline_media_params` 写回 canonical；sandbox 端点持久化 canonical、执行时 materialize。

`purpose` 只用于错误信息/审计，远程形态统一保留、不按 purpose 拒绝；远程 URL 不下载，SSRF/外链风险沿用现状并由部署层出网策略约束。

- **A23**：A 提交 B 的 `/code/result/...` → 404，且未发生 MinIO 下载；
- **A24**：A 提交 B 的 `users/<b_key>/x.docx` → 400/404；
- **A25**：A 提交 `/app/code/result/image/<b_sid>/x.png` → 404 且未读取；`MediaController` 对绝对 URL 路径直接 404；
- **A26**：PATCH / execute / intervene 传 `public_path` → DB/GET 仍为 `public_path`，DB 中不出现 `_refs` 路径。

### 17.2 缓存根与白名单顺序

- 缓存键与 session 解耦：**`code/work/_refs/<owner_key>/<sha256(public_path)[:16]><ext>`**；只由 `ensure_local` 写入。
- 校验顺序：**先 `canonicalize` 校验归属**（public → artifact_files.owner；temp → owner_key 段），再 `materialize`；`guard_media_input` 对 `ResolvedMedia.trusted` **不再走** `get_allowed_media_roots()` 的 realpath 白名单，避免 `code/work` 被判越界。
- 原始路径仍走白名单；`code/work` 不加入用户可提交白名单。
- `_refs` 清理：按 mtime/LRU 淘汰（如 7 天或总大小上限），session 完成后可 best-effort 清理其对象；不做无限增长。

### 17.3 `ensure_local` 并发/原子/失败

- 按 `public_path` 做进程内 per-key lock；缓存命中直接返回；
- 下载写唯一 `.tmp`，`fsync` 后 `os.replace`；失败清理 `.tmp`，不暴露半文件；
- 对象缺失抛分类 `MediaMissingError`：媒体 → 404，阶段 → 明确错误；不无限重试（最多 2 次）；
- **P16**：同图 8 并发只下载一次、无半文件；**P17**：对象缺失时阶段错误可读且不写检查点；**P18**：`http(s)/oss:/data:` 输入仍可创建任务（远程形态不回归）。

### 17.6 v17 评审修订（恢复/对象/约束，现行）

> 本节覆盖前文冲突：检查点状态分离、不可变对象键、API 自报头风险、artifact 父子约束、rehydrate、pipeline 恢复、迁移幂等、任务顺序。

- **检查点与执行状态分离**：`payload_json` 始终是“最后一个 completed 快照”；`status` 只是当前执行状态。恢复查询用 `list_checkpoints(sid)`（`version > 0`），**不按 status 过滤**；`mark_running`/`fail` 不得清空 payload/version。补测：completed → 重跑 running → failed/interrupted → 重启 → 旧产物仍可恢复。
- **不可变对象键**：每次执行/上传有完整UUID4 execution_id，按§18/D11加入资源域/ID和唯一file_id；public_path携带相同身份。同名重跑不覆盖，DB只切换指针；失败只清本次未发布对象，旧检查点及已提交条目对象保持。
- **API 自报头风险**：`X-User-Login-Name` 是信任输入，API 归属过滤不构成身份认证；proposal/design 的 accepted risks 同时写“媒体 query 冒读”和“API 头可伪造”。`user-data-isolation` 场景只断言“当前声明身份与他人资源不匹配 → 404”，不得写“API 不能冒读”。
- **artifact_files 约束**：`CHECK (num_nonnulls(session_id,task_id,record_id)=1)`；父子 owner 一致性由 DB trigger + repository 双保险；`sandbox_paths.record_id` 外键级联；`artifact_files` **一个对象一行**，`public_path UNIQUE`；Pipeline 同路径多 `kind/name` 只在 `artifacts_json` 引用同一 public_path，不重复建行。补测：同路径多 artifact、跨父删除、owner 不一致。
- **恢复桥**：新增内部 `rehydrate(payload, owner)`：从 DB 读 public_path 后先查 `artifact_files.owner`，通过后重建 `ResolvedMedia` 再 materialize；**不得把 DB 字符串直接当 trusted**。
- **Pipeline/沙盒恢复**：`pipeline_tasks` 增加 `boot_id`；启动 sweep 将陈旧 pending/running 标 `interrupted`（不自动续跑）；显式重试创建**新 task_id**，旧任务只读；运行中删除返回 **409**（本期不实现 cancel）。沙盒 record_id 升 uuid/128 bit，目标表 PK 与生成器一致。
- **现有能力修改**：`workflow-state-recovery` 列入 Modified Capabilities；其“全部装载入口/幂等/不误伤在途执行”要求在 DB 检查点实现中保留。
- **迁移幂等**：`ALTER TABLE ADD CONSTRAINT` 用 `DO $$ ... IF NOT EXISTS ... $$`；验收写“迁移 runner 重入”，不承诺裸 SQL 重复执行。
- **默认 guip 升级**：无 GUIP 的存量单机环境升级前必须设 `VC_USERS__MODE=single`，否则进入身份缺失页；GUIP 就绪后再切 `guip`。
- **任务顺序**：storage/materialize 早于路由归属改造；收藏复制/列表早于 saved-media 的 A11/A27；legacy import 前移；works/counts 统一 `missing_at IS NULL` 口径；`source_deleted` 只由源行不存在派生。

### 18.2 已确定的设计决策

| 项目 | 本轮采用的决定 | 排除的实现 |
|---|---|---|
| 新文件路径 | `object_key=<owner_key>/<sessions或tasks或sandbox>/<resource_id>/<stage>/<完整execution_id>/<file_id><ext>`，public为`/code/result/_media/<object_key>` | 仅对象key变、public原地覆盖；basename去重；截断UUID |
| 发布 | 显式清单区分新文件/已索引旧引用/远程引用；先登记操作、上传、核验，再业务事务 | 遍历任意字符串上传；把旧引用改绑新父资源 |
| local | 仅legacy读取；新业务失败保留工作文件但不发布local行 | 将迁移工具的local回退套到新阶段 |

| DB与JSON | 启用一条业务链时写入和读取一起切DB，停止默认JSON双写 | JSON setdefault盖过DB；查不到DB就自动导入 |
| 推理 | core按协议给本地/HTTP候选，legacy强制HTTP用受管暂存 | 模型层查DB；裸网关/浏览器query当推理回退 |
| 空间 | 主流程+Pipeline final继续进入，sandbox不进入 | 为本组重新讨论已有产品范围 |
| 删除 | 持久对象操作日志保留定位及重试，父删除与清理意图同事务 | cascade后对已不存在的artifact行写missing |

### 18.3 统一流程与工作视图

```text
canonical snapshot + revision
  --> local execution / explicit edit
  --> new-file manifest + prepared object operations
  --> upload + existence/size verification
  --> shared DB transaction (stages + working view + session + files + retained)
  --> install committed cache revision
  --> API success / media-bearing SSE
```

本轮新增 `session_stage_working`（工作稿/preview/execution三类JSON）和 `object_operations`，sessions加content_revision；详细schema见数据库§18与design D12/D17。`list_checkpoints(version>0)`继续只代表最后成功；人工编辑已保存但不完整时另有工作稿，不能丢失或伪装completed。修订候选独立保存，取消只清候选；应用检查指纹与类型化冲突确认后，同事务更新所有受影响阶段及集数等meta。

进度中的媒体条目先发布再发事件；失败/重启不把该执行的部分结果整体覆盖成功快照。已提交条目版本仍保存，可用于显式重试；默认编辑视图使用已保存工作稿，未完成摘要以execution_preview区分。保持现有停点和用户手改优先，不以对象存储迁移改变文案/模型策略。

### 18.4 发布/消费/恢复必须配套改造

- 发布清单与消费清单分开，逐项对应design D14：characters/settings selected/versions、reference scenes selected/versions、改写的文本versions与可选grounding、video各模式参考+音频、editor选中片段与final_videos.path、三类Pipeline别名和sandbox工具。
- `_session_*` 完整注入后再物化运行副本；不改变canonical state，不下载全部版本。Agent的硬编码输出目录转受信execution根，历史版本从DB读取，不通过glob推断。
- 所有同步DB/对象I/O在线程池、全局状态锁外；以每资源短提交互斥和revision CAS控制更新。相同条目迟到模型结果只加版本、不覆盖用户selected；全剧基线冲突返回待重新预览。
- 当前跨stage不止script→character：确认续写、分镜PATCH→参考/视频、参考prompt→分镜等都由实际差异收集器归入同一事务。
- Pipeline包括create/update/append/finish/fail/read/SSE/delete/sweep，sandbox包括纯文本结果、history、paths与删除；API字段及时间格式兼容，事件提交后发。工作流启动、懒加载、列表/统计、所有保存入口同样必须收口。

### 18.5 失败、删除与回滚边界

新上传失败不创建正式文件行；上传后核验/事务失败只处理本次未retained对象。事务结果未知时先查DB操作状态，不能盲删可能已提交对象。DB成功而内存安装失败要驱逐缓存，使下一次查询真正重载。

删除前事务记录bucket/key、公有路径及精确工作/缓存文件，之后删父资源；清理器有界扫描、删除后stat确认、失败退避并保留凭据。中间产物已经提交则不因整个阶段失败被删除；旧版本本期不自动GC；收藏仍独立副本。文件在用pin阻止缓存清理，推理临时URL在远端终态/到期前不删。

正常切换后不默认写JSON，原文件只保留为备份。实际实例切换前单独确认数据已入库、备份和停写窗口；回滚恢复匹配版本的DB+对象+代码，不承诺旧代码读取本轮新工作视图。
