# D4 上下文预算规格草案（测量阶段）

- 状态：**测量阶段已完成（2026-11-04）；当前 hard=off；方向为后续 A（fail），压缩策略未启动，不改请求内容**
- 对应：D4（OP-03，承接 WF-08）、D1 观测
- 目标：先回答“单请求多大、单次执行总共多大、超了多少”，再决定是否压缩。
- 不在本草案：截断 `original_text`、摘要回退、改变请求组装、真实模型质量对照。

## 一、已有数据

D1 每条模型调用已记录：

- `input_chars`：本次 prompt 字符数（不存正文）；
- `execution_id`/`stage`/`template_name`/`model`；
- `usage` 仍可能为 unknown，不得用字符数冒充 token。

`summarize_records`/`tools/observability_report.py` 已输出：

- 按 stage/template/model/kind 的 `input_chars_p50/p95/max`；
- 单请求 `input_over_warn`/`input_over_hard`；
- 按 `execution_id` 的 `input_chars_sum/max` 与执行总量超阈值标记。

## 二、阈值（初始配置，均可调）

| 项 | 默认 | 说明 |
|---|---|---|
| 单请求 warn | 80,000 字符 | 只告警；按中文 1 字≈1 token 的经验估算（128k token 上下文，非安全线）；warn≤0 视为关闭 |
| 单请求 hard | **0（关闭）** | 128k 为 token 上下文；未定失败行为前保持关闭 |
| 单次执行 warn | 300,000 字符 | 覆盖“整剧原文发每个片段”的累计风险 |
| 单次执行 hard | **0（关闭）** | 同上 |

配置方式：`VC_OBSERVABILITY_INPUT_WARN_CHARS`、`VC_OBSERVABILITY_INPUT_HARD_CHARS`、`VC_OBSERVABILITY_EXECUTION_WARN_CHARS`、`VC_OBSERVABILITY_EXECUTION_HARD_CHARS`；报告脚本也支持同名 CLI 参数。

**上下文口径**：模型上下文约 **128k tokens**（用户确认）；`input_chars` 不是 token，不能按 128k 字符直接比较。当前 80,000 字符是经验估算（1 字≈1 token），**不等同 token，也不构成安全线**；英文会偏保守，生僻字/标点可能更多。

**语言分档**：待接入会话 `meta.language` 后再按中/英分别配置；混合剧本按主导语言计。阈值必须可配置，便于迁移环境调整。`warn<=0`/`hard<=0` 一律视为关闭，单请求与执行总量同一语义。

## 三、hard 触发行为（A/B/C，待拍板）

**当前实际状态是 `off`**：`hard=0` 时 `over_hard` 恒为 0，不产生 hard 计数；C 尚未启用。启用 hard 前必须先选定行为并写入规格。

| 选项 | 行为 | 优点 | 代价/前置条件 |
|---|---|---|---|
| **A（建议作为未来 fail 模式）** | 超过 hard 显式失败：返回可读错误与预算信息，不调用模型、不静默截断 | 防止上下文溢出/费用失控；语义确定、可测试 | 会阻断大请求；需要前端错误展示与重试/改写引导；阈值必须来自真实分布 |
| B | 回退摘要/受限上下文：自动压缩后续跑 | 不阻断流程，成本可控 | 需要先修订“全部前序摘要”规格；必须有质量对照与回退开关；实现复杂度最高 |
| C（count 模式，未启用） | hard>0 且显式模式为 count 时仅记录 hard 事件，不改变请求 | 零行为风险，先收集真实分布 | 不提供硬保护；费用/溢出风险仍由供应商兜底 |

**决策**：现在保持 **off**；方向为后续启用 **A（fail）**（需真实分布校准阈值）；B 暂缓到 OpenSpec 修订与质量验收之后，不先做“静默摘要”。

**A 的启用前置**：
- 单请求/执行 hard 阈值经真实分布校准；
- 前端能显示“上下文超限”与建议（缩短本集/拆分片段/清理参考图）；
- 有 mock 用例证明超限请求不调用模型、under-limit 正常通过；
- 超限返回 **4xx**（不是通用 500），错误体含当前值/阈值/stage；H3 与视频阶段都能把该错误显示到对应条目/阶段错误卡片，并给出可操作建议；
- 不自动改写用户正文或 `original_text`。

**B 的启用前置**：
- 先修订现行“全部前序摘要”要求（另开 change）；
- 固定样例覆盖换装、道具转移、场景重访、长距离伏笔；
- 质量对比通过，保留原策略可回退。

**hard 模式设计（尚未实现）**：hard 阈值与行为分离，未来使用独立开关
`VC_OBSERVABILITY_HARD_MODE=off|count|fail`，默认 `off`。这样未来可先用 `count` 收集 hard 事件，
再切换 `fail`，不会因为把 hard 阈值调大而突然开始阻断请求。阈值仍由
`VC_OBSERVABILITY_INPUT_HARD_CHARS`/`VC_OBSERVABILITY_EXECUTION_HARD_CHARS` 控制。

## 四、验收（测量阶段）

1. 固定 fixture：单次执行 20 个片段，每片段 `input_chars` 可查，执行汇总 sum/max 正确；
2. 阈值 warn/hard 可配置；hard=0 时 `over_hard=0`，不误报；
3. 报告输出 stage/template 的 P50/P95/Max 与执行总量 Top-N；
4. 不记录 prompt 正文/URL/密钥；
5. 不改变任何模型请求内容；只增观测字段与报告。
