# D4 上下文预算规格草案（测量阶段）

- 状态：**草案；仅做测量/告警，不改请求内容**（2026-11-04）
- 对应：D4（OP-03，承接 WF-08）、D1 观测
- 目标：先回答“单请求多大、单次执行总共多大、超了多少”，再决定是否压缩。
- 不在本草案：截断 `original_text`、摘要回退、改变请求组装、真实模型质量对照。

## 一、已有数据

D1 每条模型调用已记录：

- `input_chars`：本次 prompt 字符数（不存正文）；
- `execution_id`/`stage`/`template_name`/`model`；
- `usage` 仍可能为 unknown，不得用字符数冒充 token。

`summarize_records`/`tools/observability_report.py` 已输出：

- 按 stage/template/model/kind 的 `input_chars_p50/p95/max`；
- 单请求 `input_over_warn`/`input_over_hard`；
- 按 `execution_id` 的 `input_chars_sum/max` 与执行总量超阈值标记。

## 二、阈值（初始配置，均可调）

| 项 | 默认 | 说明 |
|---|---|---|
| 单请求 warn | 20,000 字符 | 只告警，不阻断 |
| 单请求 hard | **0（关闭）** | 未定失败行为前保持关闭 |
| 单次执行 warn | 300,000 字符 | 覆盖“整剧原文发每个片段”的累计风险 |
| 单次执行 hard | **0（关闭）** | 同上 |

配置方式：`VC_OBSERVABILITY_INPUT_WARN_CHARS`、`VC_OBSERVABILITY_INPUT_HARD_CHARS`、`VC_OBSERVABILITY_EXECUTION_WARN_CHARS`、`VC_OBSERVABILITY_EXECUTION_HARD_CHARS`；报告脚本也支持同名 CLI 参数。

**语言分档**：待接入会话 `meta.language` 后再按中/英分别配置；混合剧本按主导语言计。阈值必须可配置，便于迁移环境调整。

## 三、hard 触发行为（待定，暂不启用）

可选项：

- A：显式失败并提示“请求上下文超限”，不静默截断；
- B：回退到摘要/受限上下文（需先有质量验收）；
- C：仅记录 hard 事件，不改变请求。

当前默认 C（hard=0，仅统计）；在 A/B 未定前不得启用 hard，避免制造新的失败路径。

## 四、验收（测量阶段）

1. 固定 fixture：单次执行 20 个片段，每片段 `input_chars` 可查，执行汇总 sum/max 正确；
2. 阈值 warn/hard 可配置；hard=0 时 `over_hard=0`，不误报；
3. 报告输出 stage/template 的 P50/P95/Max 与执行总量 Top-N；
4. 不记录 prompt 正文/URL/密钥；
5. 不改变任何模型请求内容；只增观测字段与报告。
