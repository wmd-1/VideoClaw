## 2. 总规则

| 编号 | 规则 |
|---|---|
| **R1 可编辑窗口** | 剧本只能改到"点『确认并继续』之前"。进入下游后对**用户**只读（系统受信回写除外）。 |
| **R2 三触发自动重解析** | 质检应用/撤销、手改正文/增删集、AI 修改应用（含单集）→ 自动更新 cast。 |
| **R3 只按正文触发** | 触发键 `structure_fingerprint(scope="body")`；cast-only 变化、阶段 2 回写、provenance/建议变化都不触发。 |
| **R4 重解析是独立后台态** | 不占阶段 `running/error`；独立状态、独立停止、独立轮询。 |
| **R5 下游硬门只看就绪** | 下游执行/介入只校验 `cast_reparse ready`；**不**因 `script_locked` 拒绝（否则进入角色阶段后永远无法继续）。 |
| **R6 锁与豁免** | 锁只拦**用户**的剧本写入；系统"阶段 2 → 剧本 cast 回写"豁免，且不改 body version。 |
| **R7 写入允许列表（含嵌套）** | 顶层与嵌套都只收白名单；服务端派生字段一律剥离/覆盖，不信任客户端值。 |
| **R8 零删除承诺** | 不删资产/成片；删除候选只建议。 |
| **R9 历史兼容** | 无 `_cast_reparse` 的会话视为 legacy-ready；`reconfirm`/`stale`/「重跑本集分镜」保留给历史会话。 |

## 3. 触发与写入收窄

### 3.1 原子登记（在与正文同一个 `_mutate` 闭包内）

- 在 `_finish_stage` 的 `apply(after)` 与 `update_artifact` 的 `apply(after)` 内：取提交前的 `body_fingerprint` 与提交后的比较；变化则在**同一事务**里写
  `after.meta["_cast_reparse"] = {"status":"pending","base_version":<新指纹>,"attempt":<+1>,"requested_at":...}`
  并清除 `accepted_stale` 相关字段。
- 事务提交成功**之后**才 `loop.call_soon_threadsafe(spawn_or_wake, sid)`。崩溃窗口内"正文已提交但 pending 未写"因此不存在。
- 不变则不登记（只改 cast / 只改 title / 空操作）。

### 3.2 顶层允许列表

**可写**：`episodes`、`characters`、`settings`、`title`、`logline`
**清除型控制键**：`pending_revision`、`pending_review`（只清除，不写入）
**服务端管理（一律拒绝）**：`meta`（含 `original_text`/`target_duration_seconds`）、`line_annotations`、`scene_spans`、`import_review`、`review_rollback`、`version`、`project_id`、`session_id`、`created_at`、`genre`、`mood`、`summary`、`overall_style`

- PATCH：顶层出现非法键 → **整包 400**（`code=script_field_not_writable`，列出非法键）。
- `modified_script`：只提取上述可写字段合并到当前 artifact；其余字段丢弃并在响应返回 `ignored_fields`（保留接口兼容，消除绕过）。

### 3.3 嵌套清洗（新增，按实测键定义）

| 容器 | 客户端可写 | 服务端管理（丢弃/覆盖） |
|---|---|---|
| `characters[]` | `name`、`description`、`species` | `character_id`、`description_source`、`description_owner`、`asset_kind` |
| `settings[]` | `name`、`description`、`mood` | `setting_id`、`description_source`、`description_owner` |
| `episodes[]` | `episode_number`、`act_title`、`content` | `line_start`、`line_end`、`episode_id`（若存在） |

规则：
1. **已有条目**按服务端主键（`character_id`/`setting_id`/`episode_number`）匹配；客户端带来的主键只用于匹配，**不直接采信**；匹配成功则保留原主键与派生字段。
2. **新条目**（无主键或主键不存在）由 `ensure_item_ids` 派生主键；嵌套未知键丢弃并计入 `ignored_fields`。
3. `description_owner` **只能由后端 diff 计算**（见 §7），客户端值一律忽略。
4. 嵌套字段缺失（如 `mood` 未传）视为不修改，不做隐式清空；显式 `null` 视为清空（仅限可写字段）。

### 3.4 `confirm_continue` 不再预建下游产物

- 移除 `character_design` 与 `storyboard` 空壳创建，只保留剧本侧 `episodes/characters/settings` 追加。
- 分镜新集卡片：`StoryboardStage` 从 `artifacts.script_generation.episodes` 派生**只读占位卡**（"待生成"），不写下游产物。
- **确认守卫（覆盖历史空壳）**：
  ```
  storyboard 可确认 ⇔ script 的集号集合 ⊆ storyboard 的集号集合，且每个对应集 segments 非空
  ```
  不满足 → 后端拒绝（`code=storyboard_incomplete`），前端隐藏「确认并继续」（用同一判据，不是"零片段"）。

## 4. 重解析调度器（`CastSyncService`）

### 4.1 线程模型（无共享单 worker）

- startup（lifespan）创建：主循环 `loop`、**每会话任务注册表** `Dict[sid, asyncio.Task]`（单飞）、全局 `Semaphore(CAST_SYNC_MAX_CONCURRENCY=2)`。
- 提交漏斗（工作线程）只做 `loop.call_soon_threadsafe(spawn_or_wake, sid)`；`spawn_or_wake` 在会话已有任务时只更新目标版本、不新建任务（在途任务会自行 supersede）。
- 任务在调用模型前 `async with semaphore`，因此**并发上限 2 由两个独立任务实现**，不存在"单 worker + 信号量"的无效组合。
- 任务内 DB 读写与 `_mutate` 全部 `await asyncio.to_thread(...)`。
- **合并窗口**：登记 `pending` 后等待 `CAST_SYNC_SETTLE_SECONDS=1.5` 再发模型；窗口内新版本重置计时。`/status` 立即可见 `pending`。

### 4.2 状态机

```
（缺省/无记录）= ready（legacy）
pending ──(settle)──▶ running ──▶ done
   ▲                    ├──▶ failed
   │                    ├──▶ stopped
   │                    └──▶ superseded ──▶ pending(新版本)
   └── accepted_stale（仅显式接受后，终态；新正文编辑后清除）
```

- 所有写入带 `attempt + base_version` CAS；旧任务只能更新自己的 attempt。
- 运行前二次校验 `base_version == 当前 body 指纹`，不等则 `superseded`（不调模型）。
- `done` 记录 `base_version/finished_at/summary`；`failed` 记录 `error`；均**不改剧本阶段状态**。

### 4.3 取消（尽力而为）

- 每任务持 `threading.Event` 取消令牌，注入 agent `cancellation_check`。
- `stop_session`（线程池内）→ `loop.call_soon_threadsafe(task.cancel)` + `token.set()`。
- 边界：`Task.cancel()` 不能终止已发出的 `to_thread` 同步模型请求（`base_agent.py:152-154`）；停止语义 = 不提交结果、不再推进，费用可能已发生。
- 前端提供**独立**的「停止人物/场景更新」入口。

### 4.4 监督与恢复

- 每任务独立 `try/except`，异常写 `failed`；注册表在任务结束时清理（含异常路径）。
- startup 扫描：`SELECT session_id FROM sessions WHERE meta_json->'_cast_reparse'->>'status' IN ('pending','running','superseded')`
- 归一化**不直接改 JSONB**：逐条走 `_mutate` 写 `running→pending`（`interrupted_by_restart=true`）、`superseded→pending`，再入队；避免破坏 legacy meta 展开（见 §8）。

### 4.5 接口与就绪

```
GET  /api/project/{sid}/status                      # 顶层 cast_reparse / script_locked
POST /api/project/{sid}/cast-reparse/retry          # failed|stopped → pending（attempt+1）
POST /api/project/{sid}/cast-reparse/accept-stale   # 仅 failed|stopped；无 pending/running；写 accepted_stale
POST /api/project/{sid}/cast-reparse/stop
POST /api/project/{sid}/cast-suggestions/apply      # {ids, base_version}
```

就绪判据：

```
ready = 无 _cast_reparse 记录（legacy）
     OR (status == "done"          AND base_version == 当前 body 指纹)
     OR (status == "accepted_stale" AND accepted_base_version == 当前 body 指纹)
```

- `accept-stale` 前置：状态 ∈ {failed, stopped}；若存在 pending/running → 409 `reparse_busy`（先停止/等待）。
- 接受写审计：`accepted_by/accepted_at/accepted_base_version`；任何新正文编辑（body 指纹变化）→ 状态回到 `pending` 并清除接受标记。

## 5. 剧本锁

### 5.1 判据（不看裸 status）

```
script_locked = current_stage 已越过剧本（启用序列；不在序列内用固定全序兜底）
             OR 存在下游 execution 记录
             OR 存在下游"有意义产物"

meaningful_artifact(stage) =
  character_design     : characters 或 settings 非空
  storyboard           : 任一 episode 的 segments 非空
  reference_generation : reference 模式 → 带跳过标记即算；否则 scenes 非空
  prompt_rewrite       : items 非空
  video_generation     : clips 非空
  post_production      : final_videos/final_video 非空
  其它/新增阶段        : 任一列表字段非空（兜底）
```

### 5.2 拦截点（锁与就绪分开）

| 入口 | 校验 |
|---|---|
| `PATCH /artifact/script_generation`（可写字段/嵌套改写） | `script_locked` → 409 |
| `/intervene` 剧本 action（`revise_script/apply_revision/modified_script/confirm_continue/delete_continue/review_script/apply_script_review/rollback_script_review/reparse_cast`） | `script_locked` → 409（在 `prepare_intervention_execution`，SSE 前） |
| `/execute/stage=script_generation`（重新生成） | `script_locked` → 409 |
| `prepare_stage_execution`（下游阶段） | **仅校验 `cast_reparse ready`**，不校验锁；在 `_ensure_stage_seeded` 之前 |
| `prepare_intervention_execution`（下游阶段 action） | 仅校验 `ready` |
| `_continue_workflow` | 确认剧本时校验 `ready`；确认下游阶段不受锁影响 |
| `_begin_stage` / `_mutate` 提交闭包 | 剧本用户写入再校验锁（防 prepare 后跨锁）；下游执行不校验锁 |
| 重解析结果写回 | 仅写 `characters/settings`（嵌套白名单），不得改正文 |

SSE：准备期冲突 → HTTP 409；流开始后的冲突只能发 `error`（`code` 同上）。

### 5.3 系统回写豁免

- 阶段 2 完成时 `name/description/species` 回写属受信内部写入：允许、不触发重解析（body 不变）、保留条目 `description_owner`。
- 用户 PATCH 全部经过 §3 白名单与锁；内部回写直接改 `state.artifacts`，不经过这两道。

### 5.4 前端

- `ProjectStatus` 增加 `script_locked` 与 `cast_reparse`；前端只消费不自推。
- 剧本页 6 类编辑控件禁用 + `title` 原因；顶部说明条：
  > 剧本已进入角色阶段，正文与角色/场景已锁定；如需修改请新建会话。
- 「确认并继续」在 `ready != true` 时禁用并提示"正在更新人物与场景…"。

## 6. 前端数据流

- `pending/running` → 启动专用轻轮询（1.5s，`done/failed/stopped/accepted_stale` 即停）；会话载入/刷新同样启动。

## 7. Provenance（`description_owner`）

- 新字段 `description_owner: "user" | "model"`；与导入语义字段 `description_source`（`uploaded`/`inferred`）并存。
- 初值映射：`uploaded → user`（受保护）；`inferred`/缺失 → `model`。

| 写入口 | owner |
|---|---|
| 剧本 PATCH（characters/settings） | 后端 diff：描述实际变化的条目 → `user`；未变化保留原值；客户端传值忽略 |
| 阶段 2 PATCH（描述/名称） | 手改字段 → `user`（当前完全缺失，需新增 diff） |
| 阶段 2 模型生成 | `model` |
| 阶段 2 → 剧本回写 | 复制阶段 2 条目的 owner |
| AI 修订应用 | 描述实际变化且用户确认 → `model`；未变化保留；单集修订触发重解析 |
| 重解析 | 只更新 `owner=="model"`；`user` 只出建议 |
| 种子化/重建/后台单条重生成 | 保留 owner（`ensure_item_ids`、重建复制、`_prefer_user_edits`、`_BACKGROUND_PROTECTED_FIELDS` 都补 owner 保护） |
| 采纳建议 | `model` |

- 指纹排除：`description_owner` 同时加入 `structure_fingerprint` 的 `dropped` 与 `content_fingerprint` 的排除集。
- 建议层：`session.meta["_cast_suggestions"] = {base_version, generated_at, items:[{id,kind,name,description?,reason}]}`，不入 artifact、不进指纹；`/status` 顶层投影；新 body 版本自动失效。
- 删除候选：全剧确定性名称出现检测；改名只建议（角色/场景独立匹配），不改主键。

## 9. 撤销质检

- 校验口径：`structure_fingerprint(scope="body")` + `_review_aux_fingerprint`（不再用 all）。
- `rollback_snapshot` 增加：`cast_snapshot`（`characters`/`settings` 深拷贝）+ `cast_fingerprint`。
- 撤销时：若当前 cast 指纹 == 快照指纹（期间无手改/重解析）→ 恢复 cast；否则只回滚正文与标注，返回 `cast_restored=false` + 差异摘要。
- 撤销成功后**对称触发**一次重解析。

| A7 | PATCH 顶层出现 `meta` → 400 整包；`pending_review:null` 仍可清除 |
| A8 | 嵌套：客户端伪造 `description_owner=model` → 被忽略（后端按 diff 计算）；客户端带旧 `character_id` → 只用于匹配，不覆盖服务端主键 |
| A9 | 重解析中刷新/关页 → 后端继续；进程重启 → 扫描 `_cast_reparse` 恢复并重跑 |
| A10 | 重解析中停止 → `stopped`，不提交结果；剧本阶段状态不变 |
| A11 | `failed` → 进下游被拒；`retry` 成功后可进 |
| A12 | `accept-stale`：仅 failed/stopped 可用；有 pending/running 时 409；接受后版本匹配可进；再改正文 → 回到 pending 并清除接受 |
| A13 | 历史会话（无 `_cast_reparse`）→ legacy-ready，可正常进入下游 |
| A14 | 锁：进入角色阶段后 9 个剧本 action + PATCH + `execute script` 全 409；仅 `title/logline` 成功 |
| A15 | 锁：阶段 2 完成的 cast 回写不被拦、不触发重解析 |
| A16 | 空壳：`confirm_continue` 不创建下游产物；历史空壳的 storyboard 确认被拒；前端按钮按"集覆盖 + 非空"隐藏 |
| A17 | 新集在分镜页以"待生成"占位卡出现（派生自剧本），无下游产物写入 |
| A18 | provenance 全链路：剧本手改→user、阶段 2 手改→user、模型生成→model、AI 覆盖→model、未变保留；两指纹均不含 owner |
| A19 | Agent 输入不含 `_cast_reparse` / `_cast_suggestions`（允许 `_session_meta/_session_artifacts/_session_owner/_runtime_map`） |
| A20 | legacy meta：加内部键后 `project_params` 仍展开，且 `_` 键被合并回读模型 |
| A21 | `/status` 顶层字段与前端类型/只读化/轮询一致（`tsc` 通过） |

## 11. 风险与取舍

| 风险 | 缓解 |
|---|---|
| 多次编辑=多次付费 | body 指纹触发 + 1.5s 合并 + 会话单飞 + 版本 CAS |
| 停止不能终止在途请求 | 声明尽力而为；不提交结果；UI 明示 |
| 并发 2 仍排队 | 可配置；极端 600s 超时下用户可见 `pending` |
| 锁太死 | 按用户口径不开口子；说明条引导新建会话 |
| 历史空壳/`reconfirm` | 空集确认守卫 + legacy-ready + reconfirm 兼容；不做批量迁移 |
| allowlist 收窄影响外部集成 | `modified_script` 忽略并回报；PATCH 400 带清单 |
