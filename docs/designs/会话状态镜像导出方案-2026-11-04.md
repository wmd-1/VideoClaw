# 会话状态镜像导出方案（宿主只读查看；含 Pipeline 任务与沙盒记录）

- 日期：2026-11-04（v2，同日按用户拍板扩范围）
- 状态：**设计提案，未实施**；四项关键口径已拍板（见 §13），实施前需转 OpenSpec 四工件（proposal / specs / design / tasks）
- 需求来源：会话元数据与各阶段产物（含剧本正文）现在唯一存放在 PostgreSQL，宿主上 `data/` 里只剩执行临时根与 `_refs` 缓存，**不方便直接查看**；希望把这些结构化状态在 `data/` 下留一份人类可读的镜像，并同样覆盖 Pipeline 任务与沙盒记录。文件名沿用"会话状态镜像"，任务/沙盒为同一机制的两类额外 domain。
- 本文口径基于当日实测：`sessions` 最新会话 1793779524872（11-04 16:05）、`session_stage_artifacts.script_generation=completed 16:07:23`、`artifact_files` 99 行全部 `storage_kind=minio`、`videoclaw` 桶 99 个对象全部 `.../legacy/...`、`data/code/result/` 当日零新增。

## 1. 目标与非目标

**目标**

1. 把**已提交**的会话元数据 + 各阶段产物（剧本正文、角色/场景描述、分镜、改写提示词、选中版本引用、状态图）以 JSON/Markdown 形式镜像到宿主可直接打开的目录（`./data/code/mirror/`）；**同等覆盖 Pipeline 任务与沙盒媒体工具记录**（2026-11-04 已拍板，见 §13）。
2. 镜像**只用于查看/grep/比对**，人一眼能看懂，且能自证"是不是最新"（带 revision 与导出时间）。
3. 零风险侵入：不改状态源、不改契约、不动前端，关闭开关后行为与现在完全一致。

**非目标**

- ❌ 双向同步：镜像里的文件被手工编辑后**不会**回写 DB（且在文件里写明这一点）。
- ❌ 复制媒体二进制：图/视频仍在 MinIO，镜像只写"引用 + 对象键 + 大小"清单。
- ❌ 实时镜像运行中间态：运行中的内存 overlay 进度不进镜像（阶段中间进度已由 `session_stage_working` / `stage_progress_json` 落库，能反映到下一次导出）。
- ❌ 恢复/备份用途：备份仍以 `pg_dump` + MinIO 桶为准，镜像缺失不影响任何功能。

## 2. 数据来源（唯一读取入口，不新增 SQL 面）

| 镜像内容 | 现成读取入口 | 说明 |
|---|---|---|
| 会话外壳（owner/status/current_stage/`status_json`/`stage_progress_json`/`meta_json`/revision/updated_at） | `db.repositories.commits.load_committed(sid)` | 单一 REPEATABLE READ 只读快照，与 `/status` 恢复用的同一契约 |
| 各阶段产物正文 `checkpoints[stage]` + `checkpoint_versions[stage]` | 同上 | **权威=最后好检查点**，不含 preview |
| 工作层 / 预览层 / 执行层（含 `missing_inputs`、上次未完成执行） | 同上 `working[stage]` | 单独成文件，避免与检查点混淆 |
| 媒体引用对照（`public_path → bucket/object_key/kind/size/missing_at`） | `db.repositories.FileRepo().list_by_session(sid)` | 已存在，无新 SQL |
| 会话清单（枚举与变更判定） | `db.repositories.SessionRepo().list_all()` | 已存在 |
| Pipeline 任务（`input_json`/`output_json`/`artifacts_json`/progress/status/error） | `pipelines.storage.task_view(TaskRepo().get(task_id))` | 视图函数已存在，含 epoch-ms → ISO 转换，镜像直接复用不再拼字段 |
| 任务清单（枚举） | `TaskRepo().list_all()` | **需新增**（现仅有 `list(owner, limit)`，无跨 owner 枚举） |
| 任务媒体对照 | `FileRepo().list_by_task(task_id)` | 已存在 |
| 沙盒记录（`tool`/`model`/`input_json`/`output_json`/`files_json`） | `api/routers/sandbox.py::_record_view(row)` 同源 | `_record_view` 是路由私有函数；镜像层另写等价的字段投影，避免导入路由模块 |
| 沙盒清单 / 路径归属 | `SandboxRepo().list_all()`、`SandboxRepo().paths_of(record_id)` | **均需新增**（现仅有 `list(owner, limit)` 与 `owner_of_path`） |
| 沙盒媒体对照 | `FileRepo().list_by_record(record_id)` | **需新增**（`artifact_files.record_id` 列与 `ix` 均已在 001 迁移里，仅缺查询方法） |

上述四处新增都是**只读查询方法**，不改 schema、不加列、不加触发器、不碰任何写链路与检查点事务。

读 DB 而非读 `workflow_engine` / `runner` 内存态，理由：镜像必须只反映**已提交**内容，不能被进程内 overlay 污染，也要能在后端重启/切换实例后照常工作。

## 3. 落盘位置与目录布局

```text
./data/code/mirror/                      # 容器内 /app/code/mirror（该挂载为 rw，compose 无需改动）
├── README.md                            # 导出器自动写入：声明只读、非状态源、勿手改
├── index.json                           # 全局索引：schema 版本、导出时间、各类资源数、上次错误计数
├── sessions/<owner_key>/<session_id>/
│   ├── _index.json                      # 会话外壳（见 §4）
│   ├── script.json                      # 剧本正文（checkpoints["script_generation"]）
│   ├── script.md                        # 剧本可读渲染
│   ├── character_design.json
│   ├── storyboard.json
│   ├── prompt_rewrite.json              # 仅 H3 改写开启时存在
│   ├── reference_generation.json
│   ├── video_generation.json
│   ├── post_production.json
│   ├── _working.json                    # 工作层/预览层/执行层 + missing_inputs
│   └── media.json                       # 该会话 artifact_files 全量对照表
├── tasks/<owner_key>/<task_id>/
│   ├── _index.json                      # pipeline/status/progress/message/error/时间戳/duration
│   ├── input.json                       # task_view["input"]（canonical 值，非物化副本）
│   ├── output.json                      # task_view["output"]
│   ├── artifacts.json                   # 已发布的中间产物条目（path 均为 public）
│   └── media.json                       # FileRepo().list_by_task 投影
└── sandbox/<owner_key>/<record_id>/
    ├── _index.json                      # tool/model/created_at
    ├── input.json                       # input_json（含参数，不含秘密）
    ├── output.json                      # output_json
    └── media.json                       # list_by_record 投影 + sandbox_paths 列表
```

要点：

1. **独立命名空间 `mirror/`**，绝不落在 `code/result/**` 或 `code/data/sessions/**` —— 后者是 `legacy_import` 与旧清理逻辑的扫描面，写进去会重新制造"JSON 是不是状态源"的歧义（已归档 openspec 与 `用户与个人空间-数据库方案.md` 都把这两处定义为 legacy 只读）。
2. 目录段用 `owner_key = sha256(login.strip())[:16]`（与对象键同一函数 `core/media_refs.owner_key`），避免中文/`@`/保留名进路径；`_index.json` 内同时写 `owner` 原文供人核对。
3. 阶段文件名沿用 `WorkflowStage` 枚举值（`script_generation`/`character_design`/`storyboard`/`prompt_rewrite`/`reference_generation`/`video_generation`/`post_production`），与 DB `stage` 列、前端阶段键一一对应，不做二次命名。
4. 每个 `<session_id>` 目录内文件集合 = 该会话已有检查点的阶段；未跑到的阶段**不生成空文件**（避免"空文件=产物丢失"的误读）。
5. 任务/沙盒与会话同构：一个资源一个目录、目录名 = 资源 ID、按 `owner_key` 分区。沙盒 `record_id` 与任务 `task_id` 都已是服务端生成的安全标识（`task_id` 形如 `20261029_015308_9d0e04f0`），仍按 M4 再校验一次。
6. 任务/沙盒是**单向追加**的历史：默认只镜像最近 `max_items_per_domain`（默认 200）条，更早的不补；已终态（`completed`/`failed`/`interrupted`）的任务不再重写。

## 4. 文件格式

### `_index.json`（会话外壳）

```json
{
  "mirror_schema": 1,
  "exported_at": "2026-11-04T16:20:31+08:00",
  "source": "postgresql:videoclaw",
  "boot_id": "79183d1bc97743b49ef139da57e1b59c",
  "session_id": "1793779524872",
  "owner": "someone@example",
  "owner_key": "25bf8e1a2393f110",
  "content_revision": 4,
  "db_updated_at": 1793779643000,
  "status": "running",
  "current_stage": "character_design",
  "status_map": { "script_generation": "completed", "character_design": "running" },
  "stage_versions": { "script_generation": 4 },
  "meta": { "...": "sessions.meta_json 原样" },
  "note": "本文件为只读镜像，非状态源；修改此文件不会回写数据库"
}
```

- 阶段 JSON 内容 = `checkpoints[stage]` 原样（不裁剪、不改名），只在最外层加 `_mirror` 元信息小块：`{"_mirror": {"stage": "...", "version": 4, "exported_at": "..."}, ...原 payload}`。
  - 例外：不复制可由既有字段推导的冗余正文（沿用既有口径，如视频阶段不落 `effective_prompt`）。
- `media.json` = `FileRepo().list_by_session` 的字段白名单投影（`file_id/stage/kind/public_path/storage_kind/bucket/object_key/media_type/size_bytes/missing_at/created_at`）；`local_path` **默认不导出**（那列对 legacy 行是 `/app/code/result/...` 容器内绝对路径，在宿主上读起来误导）。
- `script.md` 渲染规则（纯函数，失败不影响 JSON）：`title / logline / genre / mood / meta.tone / meta.film_type` 抬头，`characters[]`（名称+描述）、`settings[]`、`scene_spans[]` 分节；正文取 `meta.original_text`（有则优先）否则由 `scenes` 拼装。

### `_index.json`（Pipeline 任务 / 沙盒，与会话同一外壳字段集）

```json
{
  "mirror_schema": 1,
  "domain": "tasks",
  "resource_id": "20261104_161203_ab12cd34",
  "owner": "someone@example",
  "owner_key": "25bf8e1a2393f110",
  "fingerprint": "sha256:8f1c…",
  "exported_at": "2026-11-04T16:13:02+08:00",
  "pipeline": "ref2va",
  "status": "completed",
  "progress": 100,
  "duration_seconds": 41.2,
  "note": "本文件为只读镜像，非状态源；修改此文件不会回写数据库"
}
```

- 任务字段一律取 `pipelines.storage.task_view()` 的输出（已有 epoch-ms → ISO 转换与字段命名），镜像层不重新拼字段；沙盒同理取 `_record_view` 等价投影。
- **不外露本地路径**：`task_view` 里的 `output_dir`（指向已删除的执行工作根）与 `artifact_files.local_path` 同策略默认不导出，只在 `_index.json` 里留 `"output_dir_omitted": true` 说明位；需要时用 CLI `--include-local-paths` 显式打开（Q5）。
- 沙盒 `input_json` 可能含用户粘贴的提示词与参考图引用：只白名单取参数字段，参考图一律以 `public_path` 形式出现，不拼 `media_ref_base_url` 也不生预签名 URL（那类值有 TTL，写进文件只会误导）。

**时间与编码**：`ensure_ascii=False`、`indent=2`、UTF-8、行尾 LF，宿主 `grep`/`diff` 友好。

## 5. 八条不变量（实现必须逐条有断言）

| # | 不变量 | 落实方式 |
|---|---|---|
| M1 | 镜像不是状态源 | 全仓除 `core/state_mirror.py` 外无人读 `mirror/`；`load_sessions()`/恢复链零改动；测试断言删除整个 mirror 目录后阶段执行与 `/status` 不受影响 |
| M2 | 导出失败绝不影响业务 | 导出体 `try/except Exception → logger.warning + 错误计数`，与 `PersistenceService._install` 的"缓存异常不得影响已提交结果"同构；测试用注入异常反证阶段照常提交 |
| M3 | 目录隔离 | 只在 `CODE_DIR/mirror` 下写；`mirror` 不得与 `work/executions`（`work_roots_base()`）或 `_refs` 重叠；启动时若 `mirror` 根位于这两者内 → 直接禁用并告警 |
| M4 | 归属分区 | 路径段 `owner_key`，`session_id` 走既有 `_is_valid_upload_identifier` 同款校验；目录名一律 `_segment()` 式拒绝 `/ \ .. \x00` |
| M5 | 原子写 + symlink 拒绝 | `tmp` + `os.replace`；写前逐级 `os.path.islink` 复核（复用 `assert_plain_work_root` 的判定风格），任一级 symlink 即拒绝该路径并告警，绝不跟随 |
| M6 | 可判断新鲜度 + 不重复写 | 每个 `_index.json` 带 `fingerprint = sha256(拼装后的权威视图 JSON)`（会话另记 `content_revision` 与各阶段 `version`）；fingerprint 未变则不重写。**比对基准从文件自身读回**（内存表丢了也不致于重启即全量重写），因为 `pipeline_tasks` 只有 `updated_at`、`sandbox_records` 连 `updated_at` 都没有，单靠 revision 列无法统一三类资源 |
| M7 | 不含秘密 | 白名单字段导出；绝不写 `config.yaml` 内容、DSN、API key、`local_path`（见上） |
| M8 | 幂等 + GC | 会话/任务/沙盒记录删除后由导出器下一 tick 移除其镜像目录（仅限 `mirror/{sessions,tasks,sandbox}/<owner_key>/` 下的普通目录，`shutil.rmtree` 前 M5 复核）；孤儿目录（DB 中已无父行）同样清理；对应 `prune_empty_execution_dirs()` 的"只删空目录"哲学在此扩展为"只删 mirror 根内已确认无父行的目录"，且不跨 domain 递归 |

## 6. 触发方式（三档，已选 B + C）

| 档 | 时机 | 延迟 | 侵入面 | 评价 |
|---|---|---|---|---|
| A 即时 | `PersistenceService.commit` 返回后入队，守护线程消费 | 秒级 | 挂在核心提交链路上 | 收益（早几秒）不抵风险，**不采用** |
| **B 定时增量** | 复用 `start_cleanup_loop` 同款模式起一个导出线程：启动做一次全量补齐，之后每 `interval_seconds`（默认 60）扫三类 `list_all()`，只重写 fingerprint 变化的资源，每 tick 每 domain 最多 `max_items_per_tick` 个 | ≤60s | 零核心链路改动 | **主用** |
| **C 手动 CLI** | `python -m core.state_mirror --all` / `--domain sessions\|tasks\|sandbox` / `--owner <login>` / `--session <sid>` / `--task <id>` / `--dry-run` / `--out DIR` / `--prune-orphans` | 立刻 | 独立入口 | 需要"现在就有一份"、排障与测试都用它 |

B 的变更判定统一用 M6 的视图 fingerprint（而非单靠 `sessions.content_revision`）：`pipeline_tasks` 只有 `updated_at`、`sandbox_records` 连 `updated_at` 都没有，靠列语义无法一套逻辑盖住三类资源。进度类小字段（`stage_progress_json`、任务 `progress`）仍会进 fingerprint，但因为整个 payload 一起哈希，它只会导到“多写一个文件”，不产生额外 DB 读；仍保留两道限流：每 tick 每 domain 条数上限 + 已终态任务不重写。

线程生命周期与 boot 语义：与清理器同生同灭（`lifespan` 内启动、`shutdown` 置 stop event）；单实例假设不变，不引入跨进程协调。

## 7. 配置项

`config.yaml` 新增段（默认关闭）：

```yaml
mirror:
  enable: false
  dir: ''                 # 空 = CODE_DIR/mirror
  interval_seconds: 60
  include_working: true   # 是否写 _working.json
  render_markdown: true   # 是否写 script.md
  include_tasks: true     # 已拍板：本期就覆盖 Pipeline 任务
  include_sandbox: true   # 已拍板：本期就覆盖沙盒记录
  max_items_per_tick: 50  # 每 domain 每 tick 上限
  max_items_per_domain: 200  # 只镜像最近 N 条（任务/沙盒历史）
```

需要同步改的四处（缺一会出现"配了不生效"或"未知 VC_ 告警"）：

1. `config.py`：`ENV_MIRROR_PATTERN = re.compile(r"^VC_MIRROR__([A-Z0-9_]+)$")` + 收集 `mirror_fields` + 合并进 `effective.setdefault("mirror", {})`；
2. `config.py` 未识别告警前缀白名单（`if key.startswith((...))`）追加 `"VC_MIRROR_"`；
3. `config.py` `settings` 类属性：`MIRROR_ENABLED / MIRROR_DIR / MIRROR_INTERVAL / MIRROR_INCLUDE_WORKING / MIRROR_RENDER_MARKDOWN / MIRROR_INCLUDE_TASKS / MIRROR_INCLUDE_SANDBOX / MIRROR_MAX_PER_TICK / MIRROR_MAX_ITEMS_PER_DOMAIN`；
4. `config.yaml.example` + `.env.example` 增加注释块（照现有中文注释风格，写清"只读镜像、非状态源、备份仍以 pg_dump + MinIO 为准"）。

env 覆盖示例（`docker compose restart backend` 即生效，属"改代码/改 config 走 restart"口径；若在 `.env` 里改 `VC_MIRROR__ENABLE` 则需 `docker compose up -d` 重建容器才会重读 env_file）：

```bash
VC_MIRROR__ENABLE=true
VC_MIRROR__INTERVAL_SECONDS=30
```

生效性实测项（不可省）：设置页 `GET/PUT /api/settings` 的写回是否会丢弃未识别段 —— 需确认 `mirror` 段保存后仍在（若被丢弃，则只走 env/yaml 手改，并在文档里写明）。

**收藏（`saved_items` + `videoclaw-saved` 桶）本期不做镜像**：它已由 `/space` 页面直接可见，镜像价值低且需再开一处只读枚举方法；如需可后续单独提一个小 change。

## 8. 与既有机制的影响核对表

| 既有机制 | 是否受影响 | 结论 |
|---|---|---|
| DB-only 工作流、检查点恢复 | 否 | 只读 DB、单向写出，M1 |
| `work/executions` 工作根清理、`prune_empty_execution_dirs` | 否 | `mirror/` 不在 `work_roots_base()` 内，两者互不触碰 |
| `_refs` 缓存与 `prune_refs` | 否 | 不同根，容量互算不上 |
| `object_operations` 清理器 | 否 | 镜像文件不是对象存储目标，不登记操作；`count_in_flight` 判定不受影响 |
| `MediaController` / 媒体鉴权 | 否 | 不新增静态挂载、不恢复 `StaticFiles`；`media.json` 里的 object_key **不构成授权**，仍只能走带归属校验的媒体接口 |
| `legacy_import` | 否 | 不写 `code/data/sessions`、不写 `code/result`；CLI 扫描面不变 |
| `orchestrator` 旧产物清理（`RESULT_DIR` 下 script/image/video） | 否 | 该清理以 `RESULT_DIR` 为根，与 `mirror/` 无交集 |
| 用户空间隔离 | 是（正向） | 按 `owner_key` 分区，与既有归属口径一致；镜像本身不做权限控制（宿主文件权限即边界） |
| Git | 否 | `.gitignore` 已忽略 `/data/`（第 6 行），镜像不会进仓库 |
| 跨机迁移 | 是（文档） | 迁移仍需 `pg_dump` + MinIO 桶；`data/code/mirror` 只是查看便利，可整体不带；需在 `docs/reference/tips.md` 与 compose 头部注释一并说明（现注释仍写"Persistent state lives in ./data"，属上一轮已发现的过期口径） |

## 9. 体积与性能

- 当前库实测（2026-11-04）：30 个会话（阶段 payload 共约 240 kB，其中 `script_generation` 111 kB、`prompt_rewrite` 56 kB）、会话外壳字段约 31 kB、**121 条沙盒记录**（共 31 kB JSON、其中 79 条带文件行）、0 条 Pipeline 任务、99 个 `artifact_files` 行、全库 8.7 MB。
- 镜像总量估算：`indent=2` + 中文不转义后约 **0.4–0.6 MB**（不包含媒体二进制）；与库体量同阶，不会无限膨胀（会话数线性 + 终态资源不变）。
- 最坏情况：长 `submitted_prompt`（1000 字上限）× 片段数 × 版本数。默认**不截断**以保持"镜像=DB 视图"可核对；如嫌大再加可选 `truncate_strings`。
- 每 tick 成本 = 3 次 `list_all()` + 变化资源各 1 次单资读（会话 `load_committed` / 任务 `get` / 沙盒 `get`）+ 1 次 `list_by_*`；默认限流 50 条/domain/tick，写在 60s 周期内可忽略。首轮全量补齐（30+121 条）预计 < 5s。
- 不做 gzip、不做历史归档（`git` 式快照不在本期范围）。

## 12. 风险与缓解

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 镜像被误当状态源/备份源 | 目录名单独叫 `mirror/`、每个文件写 `note` 与 `_mirror.source`、README 首行声明；T6 专门反证 |

| R3 | 磁盘占用随会话/任务/沙盒线性增长 | 默认 60s + fingerprint 去重（不重写）+ 每 domain `max_items_per_domain` 上限；只读会话体积恒定；提供 `--prune-orphans` |
| R4 | 多实例部署下互相覆盖 | 现状仍是单实例约束（DB/MinIO 不解除内存态约束，见 `用户与个人空间-数据库方案.md` §2）；若未来多进程，镜像导出必须改为按 `boot_id` 分目录或只留 CLI 档 |

| R6 | 阶段 payload 结构演进导致 md 渲染崩溃 | 渲染函数纯函数 + 独立 try（失败只跳过 `.md`，JSON 必出）；schema 版本随 `_mirror_schema` 升级 |
| R7 | 为任务/沙盒新增的 `list_all()` 跨 owner 枚举，错用成业务接口会泄露他人数据 | 该方法**仅导出器（本地运维路径）使用**，不进任何 API 路由；T14 断言其只读；与现有 `SessionRepo.list_all()` 同口径（后者已仅用于启动恢复/管理面） |

## 14. 附：零改动的替代做法（若只是偶尔查看）

不改代码即可用，缺点是没有可读布局、每次手敲：

```bash
# 单会话全貌（容器内）
docker exec video-claw-postgres psql -U videoclaw -d videoclaw -c \
  "select stage, version, payload_json from session_stage_artifacts where session_id='1793779524872' order by stage;"

# 只把剧本正文导到宿主看
docker exec video-claw-postgres psql -U videoclaw -d videoclaw -tAc \
  "select payload_json->'meta'->>'original_text' from session_stage_artifacts \
   where session_id='1793779524872' and stage='script_generation';" \
  > /home/wmd/projects/VideoClaw/data/code/script_view.txt

# 媒体对照
docker exec video-claw-postgres psql -U videoclaw -d videoclaw -c \
  "select stage, kind, public_path, size_bytes, missing_at is not null as missing \
   from artifact_files where session_id='1793779524872' order by created_at;"
```

如果这类查看每周只有几次且不需要目录化，S2 之前的最小版本就是"把上面几条封成一个 `tools/export_session_state.sh`"（纯宿主脚本，不动后端）；本文 §1–§12 对应"想要常驻可读镜像"的版本。
