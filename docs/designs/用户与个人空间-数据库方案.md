# 用户与个人空间 —— 数据库与对象存储方案（PostgreSQL + MinIO）

> **状态**：设计提案（v14，未实施；替代 v1 的「SQLite 默认」与 v2 的初版 Postgres+MinIO）。本文是 [`用户与个人空间设计方案.md`](./用户与个人空间设计方案.md) 的配套子方案，已按 v6–v17 评审修订：路径模型 A、canonicalize/materialize/rehydrate、入站归属、`reference_urls`、浏览器 query+流式、saved-media（无头 query）、检查点状态分离、execution_id 不可变对象、file 级 missing、lifespan/线程池、一次性迁移 CLI。
> **决策**：元数据用 **PostgreSQL 16**，图片/视频/音频用 **MinIO**，ffmpeg 在本地工作目录执行；**每完成一个阶段写一次 DB 检查点**，用于恢复用户进度。允许重建后端镜像。
> **不做**：每用户并发/日配额（用户确认不需要）；多实例部署（单进程约束仍保留）。
> **日期**：2026-10-24。

---

## 0. 一页结论

| 维度 | 决定 |
|---|---|
| 元数据 | PostgreSQL 16，JSONB + 事务 + 索引；`sessions` / `session_stage_artifacts` / `artifact_files` / `pipeline_tasks` / `sandbox_records` / `sandbox_paths` / `saved_items` |
| 中间产物 | 剧本/角色/分镜/参考图/改写/视频/后期等 **按 stage 存 `session_stage_artifacts.payload_json`**；完成阶段时更新检查点 |
| 二进制 | MinIO 对象存储；DB 只存 `bucket/object_key/public_path/size/media_type`，不存 BLOB |
| 执行 | ffmpeg/模型仍在本地工作目录；文件先生成到本地，再上传 MinIO，最后提交 DB 检查点 |
| 恢复 | 每阶段完成 = 一个事务（stage 行 + session 行 + artifact_files）；重启后从最后一个 completed 检查点继续 |
| 身份 | 仍来自上游 GUIP；**不建 users 表**，`owner` = `login_name` |
| 并发 | 多用户/多会话可同时运行；同一 session 同时只能跑一个阶段；**不做每用户配额** |
| 单进程 | 保留 `assert_single_process_premise`；Postgres/MinIO 不解除内存态约束 |
| 依赖/镜像 | 新增 `psycopg[binary,pool]`、`minio`；`pyproject.toml`/`uv.lock` 变更，**后端镜像重建**（用户已同意） |
| 服务 | compose 增加 `postgres`、`minio` 两个服务 + 卷 + 健康检查 |

## 1. 为什么需要 DB + 对象存储

当前元数据是散落 JSON，二进制是本地文件：

- 没有事务/唯一约束/索引；收藏上限、任务状态、阶段检查点都存在「先查后写」竞态；
- 个人空间、按 owner 统计要全量扫描；
- 阶段中间产物（剧本、角色、分镜）只存在 session JSON 里，恢复时无法按阶段定位；
- 本地文件在多机/容器迁移时容易丢，MinIO 提供统一对象层。

DB 负责「可查询、可事务、可恢复」的元数据；MinIO 负责「大对象、可共享、可预签名」的二进制。

## 2. 单进程与并发（先澄清）

### 2.1 单进程是什么

`api/app.py::assert_single_process_premise()` 限制的是 **Uvicorn worker 进程数 = 1**，不是「一个用户一个任务」：

- 一个进程内 asyncio + 线程池可以同时处理很多请求；
- **多个用户、多个会话可以同时运行**；
- `_active_sessions` 只阻止**同一个 session 同时跑两个阶段**；
- 阶段内条目并发由 `enable_concurrency` / 模型并发上限（`get_max_concurrency`）控制；
- VideoClaw **没有**参考项目那种「每用户并发 1 / 每日 200」的配额（用户确认不需要）。

### 2.2 为什么仍要单进程

以下活状态只在内存：`WorkflowEngine.sessions`、`_stop_events`、`_active_sessions`、`_background_tasks`、`_boot_id`、沙盒 `SANDBOX_ACTIVE_TASKS`、SSE 进度通道。多个 worker 各一份内存，会导致重复执行、停止信号/SSE 丢失、后台任务丢失、状态互相覆盖。

**PostgreSQL + MinIO 不会解除这个约束**：DB 只让元数据一致，MinIO 只让对象共享；要真正多进程，还需要 DB 租约（`runner_id`/`lease_expires_at`）+ 外部进度/停止总线 + 任务队列 + 粘性路由。属于后续独立提案。

## 3. 参考项目实际用了什么

参考项目是 **PostgreSQL + MinIO**（不是「MinIO 数据库」）：

| 层 | 参考项目 | 本方案 |
|---|---|---|
| 关系库 | PostgreSQL；`conversations` / `conversation_turns` / `module_access_daily` / `module_access_user_mark` | PostgreSQL；会话/阶段产物/任务/沙盒/收藏表 |
| 对象存储 | MinIO，Bucket `design-agent`；会话存档 `{login}/{module}/{sid}/`；收藏独立桶不设 ILM | MinIO，`videoclaw` + `videoclaw-saved`；键含 owner |
| 本地工作区 | `/workspaces/{module}/{sid}` | `code/work/<session_id>/`（临时，ffmpeg 用） |
| 用户表 | 无；身份来自 GUIP | 无；`owner` = `login_name` |

MinIO 是 S3 兼容对象存储，不承担关系查询；Postgres 存元数据与检查点。

## 4. 阶段检查点与恢复（本方案的核心）

### 4.1 数据模型

每个会话 × 每个阶段一行：

```sql
session_stage_artifacts (
  session_id, stage,
  status,          -- pending | running | completed | failed | interrupted | stale
  payload_json,    -- 最近一次 completed 的 stage 产物（最后好检查点）
  error,
  boot_id,         -- 本阶段执行者进程标识（判断重启后的陈旧 running）
  version,         -- 每次 completed +1
  started_at,
  completed_at,
  updated_at,
  PRIMARY KEY (session_id, stage)
)
```

- `payload_json` **只在阶段完成时替换**；失败/中断不覆盖它，所以「最后一个好检查点」始终可恢复。
- `status` 表达当前执行态；`completed` 才代表可恢复。
- `version` 便于审计/排查；如需时间旅行，后续加 `stage_checkpoint_history` 追加表（本期不做）。

### 4.2 写入时机

| 时机 | 事务内容 |
|---|---|
| 阶段开始 | `stage.status=running`、`boot_id=当前进程`、`started_at=now`、`error=NULL`；`sessions.status[stage]=running`、`current_stage=stage`；**不动 payload** |
| 进度 tick | 只更新 `sessions.stage_progress_json`（可节流），不写 stage payload |
| **阶段完成** | 上传新文件到 MinIO → **一个事务**：`stage.payload_json=新产物`、`status=completed`、`version+1`、`completed_at=now`；`sessions.status/current_stage/stage_progress`；`artifact_files` 新增/更新 |
| 阶段失败/中断 | `stage.status=failed/interrupted`、`error`；`sessions.error/status`；**保留旧 payload** |
| 会话删除 | `sessions` 删除级联 stage；`artifact_files` 删除；MinIO 对象清理（best-effort） |

阶段完成事务是恢复的原子边界：要么「新 payload + session 状态 + 文件元数据」一起可见，要么都不可见。

### 4.3 恢复流程

1. 启动：`SessionRepo.list_all()` 载入会话（仅启动/管理员/导入使用）；按需加载 `session_stage_artifacts` 的 completed payload，**不批量下载对象**；运行期保留 public_path。
2. 陈旧 running：`status=running` 且 `boot_id != 当前进程` → 标为 `interrupted`（或 `failed`，取决于是否有进展），保留旧 payload。
3. 断点：`sessions.current_stage` / `status_json` 指出停在哪；用户可从最后 completed 阶段继续，或重跑当前阶段。
4. 文件校验：**不在启动全量 stat**；媒体访问时 `stat_object`，缺失 → `artifact_files.missing_at` + 404；不得改写当前 stage status 或清除最后 completed 快照；独立 `--verify` CLI 做巡检。
5. 前端：现有 `/api/project/{sid}/status` + `/artifact/{stage}` 足够；可选加 `GET /api/project/{sid}/checkpoints` 做诊断。

### 4.4 重跑同一阶段

- 开始：`status=running`，payload 仍是上一次 completed；
- 成功：替换 payload、version+1；
- 失败：status=failed，payload 仍是上一次 completed（用户可回退到最后一个好检查点）。

## 5. PostgreSQL schema

```sql
-- 001_init.sql（PostgreSQL）
CREATE TABLE IF NOT EXISTS schema_meta (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS sessions (
  session_id          TEXT PRIMARY KEY,
  owner               TEXT NOT NULL,
  owner_name          TEXT NOT NULL DEFAULT '',
  owner_org           TEXT NOT NULL DEFAULT '',

CREATE INDEX IF NOT EXISTS ix_sandbox_owner_created ON sandbox_records(owner, created_at DESC);

DO $$
BEGIN
  IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'fk_files_task') THEN
    ALTER TABLE artifact_files
      ADD CONSTRAINT fk_files_task FOREIGN KEY (task_id)
      REFERENCES pipeline_tasks(task_id) ON DELETE CASCADE;
  END IF;
  IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'fk_files_record') THEN

  END IF;

-- owner 与父资源一致性由 trigger + repository 断言（trigger 函数见仓储层迁移脚本）

ON CONFLICT (key) DO NOTHING;
```

说明：

- 无 users 表；`owner` 是 `login_name`。
- 会话的 `stage_progress` 在 `sessions`；剧本/角色/分镜等 artifacts 在 `session_stage_artifacts`；二进制元数据在 `artifact_files`。
- `artifact_files.public_path` 规范为 `/code/result/...`；`core/media_refs.to_public()` 归一 `/code/result/...`、`result/...`、`code/result/...`、`/app/code/result/...` 四种形态；`local_path` 是运行时缓存（可重建）；`missing_at` 是 file 级缺失，**不把整个 stage 判 stale**。
- `owner` 存原 `login_name`；路径/对象键使用 `owner_key=sha256(login.strip().encode('utf-8')).hexdigest()[:16]`；保留大小写、区分大小写。
- `saved_items` 用 `source_bucket`/`source_key` 指向源对象，`bucket`/`object_key` 指向收藏桶副本。
- `created_at` 统一为 epoch 毫秒；旧 sessions 的秒值（float）×1000，task/sandbox 的 ISO 字符串显式转换；`output_dir` 由 `task_id` 派生。
- `artifact_files.task_id/record_id` 外键在子表建好后 `ALTER` 添加，删除任务/沙盒级联清理。

## 6. 访问层：`backend/db/`

```text
backend/db/
├── __init__.py          # get_db() / init_db()
├── database.py          # psycopg 连接池、事务、迁移版本
├── migrations/
│   └── 001_init.sql
├── repositories/
│   ├── sessions.py      # SessionRepo
│   ├── stages.py        # StageArtifactRepo（阶段检查点事务）
│   ├── files.py         # FileRepo
│   ├── tasks.py         # TaskRepo
│   ├── sandbox.py       # SandboxRepo
│   └── saved.py         # SavedRepo
└── legacy_import.py     # JSON → Postgres 幂等导入
```

- 驱动：`psycopg[binary,pool]`（同步，连接池）；MinIO 客户端同步。
- **硬规矩：async 路由/async 引擎代码不得直接调 repo/storage**；统一 `await run_in_threadpool(...)`，否则单进程下会卡住所有人的 SSE 心跳。清单：sessions / workflow / pipelines / sandbox / space / configuration / identity。
- JSONB：写入用 `psycopg.types.json.Jsonb`；读出为 dict。
- 事务：`with pool.connection() as conn, conn.transaction(): ...`；阶段完成三张表在同一事务。
- 所有 SQL 只在 repository；所有查询必须带 owner 条件；`single` 也传 `owner='local'`，**禁止 owner=None**。
- bootstrap 不在 import 时：`WorkflowEngine.__init__` 不读 DB；`init_db`/加载/恢复在 `app.lifespan` 执行。`legacy_import` 是一次性 CLI，不在 startup 批量跑。
- migrations：`schema_meta.schema_version` + 有序 SQL；启动时事务内执行。

接口（节选）：

```python
class SessionRepo:
    def upsert(self, state) -> None: ...
    def get(self, sid: str) -> dict | None: ...
    def list(self, owner: str, limit: int = 0, offset: int = 0) -> list[dict]: ...
    def list_all(self) -> list[dict]: ...          # 仅启动/管理员/导入
    def owner_of(self, sid: str) -> str | None: ...
    def ids(self) -> set[str]: ...
    def delete(self, sid: str) -> bool: ...

class StageArtifactRepo:
    def mark_running(self, sid: str, stage: str, boot_id: str, session_patch: dict) -> None: ...
    def complete(self, sid: str, stage: str, payload: dict, files: list[dict], session_patch: dict) -> None: ...
    def fail(self, sid: str, stage: str, error: str, status: str = "failed", session_patch: dict | None = None) -> None: ...
    def list(self, sid: str) -> dict: ...          # {stage: payload}（只取 completed，供运行时）
    def list_all(self, sid: str) -> list[dict]: ... # 含 status/boot_id/version（恢复/诊断）
    def sweep_stale_running(self, current_boot_id: str) -> int: ...  # 标 interrupted，保留 payload；同事务更新 sessions.status_json
    def get(self, sid: str, stage: str) -> dict | None: ...
    def delete(self, sid: str) -> None: ...

class FileRepo:
    def upsert_many(self, files: list[dict]) -> None: ...
    def get_by_public_path(self, public_path: str) -> dict | None: ...
    def set_local_path(self, file_id: str, local_path: str) -> None: ...
    def mark_missing(self, file_id: str, missing: bool) -> None: ...  # file 级 stale
    def list_by_session(self, sid: str) -> list[dict]: ...
    def list_by_task(self, task_id: str) -> list[dict]: ...
    def delete_by_session(self, sid: str) -> None: ...
```

`StageArtifactRepo.complete()` 是检查点核心：**同事务**更新 stage 行、session 行、artifact_files 行；`mark_running/fail` 也接收 `session_patch`，避免在路由里手写 SQL。`artifact_files.missing_at` 表达 file 级缺失；缺失数由 `FileRepo.count_missing(sid, stage)` 实时 `COUNT()`，不维护易漂移的 `missing_count`。

`storage` 接口至少包含：`upload(local_path, media_type) -> (bucket,key,public_path)`、`ensure_local(public_path) -> local_path`（下载/缓存）、`presign(key, filename=None, disposition=None)`、`stat(key)`、`delete(key)`、`ensure_bucket()`。

## 7. MinIO 对象存储

### 7.1 桶与键

```text
videoclaw/                       # 会话/任务/沙盒产物
  {owner_key}/{session_id}/{stage}/{execution_id}/{filename}
  {owner_key}/{task_id}/{filename}
  sandbox/{owner_key}/{record_id}/{filename}
videoclaw-saved/                 # 收藏副本（不设 ILM）
  {owner_key}/{item_id}.{ext}
```

- `owner_key = sha256(login.strip().encode('utf-8')).hexdigest()[:16]`，避免 `@`/中文/保留名进入对象键；DB `owner` 仍存原 login；保留大小写、区分大小写。
- `artifact_files.storage_kind=minio`、`bucket`、`object_key`、`local_path`、`public_path`；`public_path` 规范为 `/code/result/...`。
- `saved_items` 用 `source_bucket`/`source_key` 指向源，`bucket`/`object_key` 指向收藏桶副本。
- 远程推理引用由 `core.media_refs.reference_urls` 产出（MinIO 预签名 + file:// 兜底；local/legacy 仅 file://）；`models/*` 不引用 DB/storage；`MEDIA_REF_BASE_URL` 仅对 legacy `file://` 生效。
- 预签名 TTL 默认 1h；若推理端可能延迟取图/重试，对齐 `VC_TIMEOUT_VIDEO` + 余量（tasks 写假设）。
- 预签名必须用 `storage.public_endpoint` 绑定的第二个 MinIO client；容器内 client 只做上传/下载/stat（SigV4 Host 不同）。
- 桶在启动时 `ensure_bucket`；主桶可配生命周期，收藏桶不设。

### 7.2 写入顺序（阶段完成）

1. 文件生成在本地工作目录（`code/work/<sid>/...`）。
2. 上传 MinIO，得到 `bucket/object_key` 与 `public_path`。
3. **路径模型 A（v7 收口）**：`state.artifacts`、落库 payload、API 统一 `public_path`；`local_path` 仅缓存；agent/ffmpeg/上传前用 `materialize` 懒加载。`materialize` 只接受 `canonicalize` 的 `ResolvedMedia`，raw `str` 必须先校验归属。
4. 组 `artifact_files` 行（`local_path` + `public_path` + bucket/key）与 stage payload（public）。
5. `StageArtifactRepo.complete()` 一个事务提交。
6. 恢复时只加载 public payload，**不批量下载**；消费点（agent 读图/ffmpeg/上传前校验）按文件 `to_local`/`ensure_local`。
7. 事务失败：删除刚上传的对象（best-effort）；对象删除失败留孤儿，定期清理。
8. 本地工作目录可清理（对象已在 MinIO）；`artifact_files.local_path` 可重建。

### 7.3 读取 / 播放

| 场景 | 方式 |
|---|---|
| 浏览器 `<video>/<img>/<a download>` | `/code/result/...?user_login=<login>` → 媒体控制器校验 query/owner → 本地/MinIO **流式返回**（Range/HEAD；下载加 `Content-Disposition`；不 302） |
| 推理服务拉参考图 | 直接生成 MinIO 预签名 URL（不再需要 `mt` 签名；也可保留本地模式） |
| ffmpeg | 从 MinIO 下载到本地工作目录 → 处理 → 上传；不能直接读对象 URL |
| 本地 fallback | `storage_kind=local`，`StaticFiles`/本地路径 |

> 浏览器媒体始终由后端流式转发（Range 分片）；预签名只给推理服务，MinIO 可仅内网/反代可达。

### 7.4 媒体控制器的归属校验

- `UserScopedStaticFiles` 改为 `MediaController`：
  - 解析 `?user_login=`（所有模式）；`single` 用 `local` 比对；
  - `artifact_files.public_path` → 查行 → owner 比对；
  - 通过 → 本地/MinIO 流式返回；
  - 失败 → 404。
- v13 起不再支持 `?mt=`；旧媒体书签返回 401/404，需重新从页面打开。

## 10. 迁移、备份、回滚

### 10.1 JSON → Postgres

- `legacy_import` 作为一次性 CLI，幂等：sessions → sessions 行；`artifacts` 按 stage → `session_stage_artifacts`（`status=completed`，`version=1`，`completed_at` 用文件 mtime/updated_at）；任务 → `pipeline_tasks`；sandbox history → `sandbox_records` + `sandbox_paths`。
- `owner` 缺失 → `users.legacy_owner`（默认 `local`）；`--fallback-owner alice` 只填空；`--reassign-from local --to alice` 显式全量改属主（dry-run + 审计）；禁止 `--owner` 模糊全量认领。
- 旧 `?mt=` 链接 v13 起 401/404；上线说明需提示重新从页面打开。
- 不删除 JSON；作为历史备份。

### 10.2 本地文件 → MinIO

- 一次性 CLI（与 `legacy_import` 同一入口）：`--files` 只处理 `owner == 目标 owner` 的文件；`--all-files` 管理员二次确认才全量上传；写 `artifact_files`（`storage_kind=minio`）。**不放 startup**。
- 未迁移的文件保持 `storage_kind=local`，媒体控制器兼容本地路径。
- 迁移后校验 `stat_object`；失败保留 local。

### 10.3 备份与回滚

- PostgreSQL：`pg_dump -Fc videoclaw > videoclaw.dump`；恢复 `pg_restore`。
- MinIO：`mc mirror` 或卷备份；收藏桶单独备份。
- 回滚：停后端 → 恢复 DB/对象 → 回退代码；旧 JSON 仍在（可作为最后兜底），但新阶段检查点只在 DB/MinIO。
- 由于 DB 是权威源，**不默认双写 JSON**；如需要过渡可保留 `legacy_import` 读取，不写回。

## 17. v14 评审修订（现行）

> 本节覆盖前文冲突；实现以本节 + 主方案 §17.6 为准。

- **检查点与执行状态分离**：`session_stage_artifacts.payload_json` 是“最后一个 completed 快照”；`status` 只表示当前执行状态。`StageArtifactRepo.list_checkpoints(sid)` 用 `version > 0` 返回 payload，**不按 status 过滤**；`mark_running`/`fail` 不得清空 payload/version。补测：completed→重跑 running→failed/interrupted→重启→旧 payload 仍可恢复。
- **不可变对象键**：每次阶段执行生成 `execution_id`（uuid4）；`object_key={owner_key}/{sid}/{stage}/{execution_id}/{filename}`；`public_path` 带 execution_id。重跑新增对象/新 public_path，DB 事务只切换 stage 指针；失败只清理本次 execution_id 的对象。`_refs` 键基于 public_path，随之失效。
- **artifact_files 约束**：`CHECK (num_nonnulls(session_id,task_id,record_id)=1)`；`owner` 与父资源 owner 一致性由 trigger + repository 断言；`sandbox_paths.record_id REFERENCES sandbox_records(record_id) ON DELETE CASCADE`，**删除冗余 `sandbox_paths.owner`**，归属通过 join 父记录；`public_path UNIQUE`，**一个对象一行**；Pipeline 同路径多 kind/name 只在 `artifacts_json` 引用，不重复建行。
- **task/sandbox 事务**：任务/沙盒完成时，`artifact_files` 与业务状态（`pipeline_tasks`/`sandbox_records`）同事务提交；失败不覆盖旧行。
- **pipeline 恢复**：`pipeline_tasks` 增加 `boot_id`；lifespan sweep 将陈旧 pending/running 标 `interrupted`，不自动续跑；显式重试创建**新 task_id**，旧任务只读；运行中删除返回 **409**（本期不实现 cancel）。
- **sandbox id**：`record_id` 使用 uuid4/128 bit；表 PK 与生成器一致；`sandbox_paths` 级联删除。
- **恢复桥**：`rehydrate(payload, owner)` 从 DB 读 public_path 后先按 `artifact_files.owner` 验证，再重建 `ResolvedMedia`；DB 字符串不得直接 trusted。
- **迁移幂等**：`ALTER TABLE ... ADD CONSTRAINT` 包在 `DO $$ ... IF NOT EXISTS ... $$`；验收为“迁移 runner 重入”，不承诺裸 SQL 重复执行。
- **works/counts**：counts 与 works 使用同一 `owner + missing_at IS NULL` 过滤；缺失对象不计入 tab 数。`source_deleted` 只由源行不存在派生，不由对象缺失派生。
- **默认 guip 升级**：无 GUIP 的存量单机先设 `VC_USERS__MODE=single`，GUIP 就绪后再切 `guip`。
