### 存储改造带来的新事实

这些不是新缺陷，但直接改变修复方式：

1. **消费计划已成为单一落点。** `core/consumption.py::plan_targets` 按阶段、模式和目标集合声明各阶段读哪些媒体字段，并由 `orchestrator._materialize_inputs` 在注入会话快照后统一物化。WF-05 的正确修法从“两个 Agent 各自拼素材”变成“校正同一份计划，并让两阶段消费同一语义顺序”。

3. **用户编辑有统一保护点。** `orchestrator._prefer_user_edits` 以 `_USER_EDIT_FIELDS`（含 `selected`、`description`、`rewritten_prompt`）保护执行期间的用户修改。它只解决“执行期间编辑被晚到结果覆盖”，**不能替代** WF-03 的选优落库和 WF-04 的提示词来源统一。

5. **版本视图已改为 DB 历史＋本次执行本地文件。** 因此“最新版本”的含义随执行根变化，任何仍以 `versions[-1]` 推断选择的逻辑都会更加不稳定。

## 二、总体判断与工作流

主链为：


**优化优先级应是“数据契约与实际输入一致性 → 提示词分型与规则一致性 → 调用及上下文预算”，而不是先大规模润色模板。**

## 五、成本、上下文与非缺陷优化机会

### 静态调用结构

以下只是正常路径代码计数，不是账单、token 或时延实测；修复、失败重试、缓存和重生成路径会改变总数。

| 环节 | 调用结构 |
|---|---|
| 初次剧本 | 7 次文本调用：分类、初稿、台词评估、情节评估、修订、资产提取、分集提取；超长／集数修复另计 |
| 分镜 | 每集一次规划、每片段一次设计、每集一次连续性检查，约 `2 × 集数 + 片段数` |
| 首帧 | 无已有 `visual_prompt` 时，每片段增加一次文本调用，随后生成／评估循环 |
| 资产图／首帧图 | 默认最多三轮生成／评估，必要时多图选优；Doctor 分支额外调用 |
| H3 | 每片段 1～3 次文本调用，另加 grounding；请求携带按模式选择的相关指南及此前连续性摘要 |
| 后期 | 当前主要按集 ffmpeg 拼接，没有提示词模型调用 |

### OP-01｜确定性分集优先，减少模型搬运完整正文

分集提取要求模型重新输出正文，而代码已有正则回退。推荐对明确标题格式先确定性切片，验证集号及正文可还原，歧义才交模型。预期减少一次长输出与正文漂移机会；解析覆盖不足是主要风险，不能直接取消模型回退。

定位：[分集提取与回退](../../video-claw/video-claw/backend/core/agents/script_agent.py#L1072-L1107)。

### OP-02｜独立评估受控并行

台词／情节评估读取同一初稿，互不消费结果，当前串行执行。可评估在现有并发配额内并行，保留两个评价维度和确定的修订输入顺序。并行降低关键路径等待，不减少 token；合并为一次评估须单独比较质量。

定位：[两次评估](../../video-claw/video-claw/backend/core/agents/script_agent.py#L1018-L1033)。

### OP-03｜连续性上下文预算

单条摘要最多 240 字符，后续请求带全部前序摘要，重复输入累计近似二次增长。可研究“长期稳定事实 + 最近镜头状态 + 相关人物／场景检索”，并保留长距离伏笔和外观变化。

这是机制变更：现行规格要求全部前序摘要，不能未经批准直接截断。应先测量上下文占用，再做质量对照，不预设节省比例。

定位：[摘要生成](../../video-claw/video-claw/backend/core/agents/prompt_rewrite_agent.py#L200-L215)、[连续性输入](../../video-claw/video-claw/backend/core/agents/prompt_rewrite_agent.py#L358-L363)、[现行规格](../../openspec/specs/h3-prompt-rewriter/spec.md#L50-L51)。

### OP-04｜显式携带风格、每镜时长和景别

H3 收集器仅拼接镜头正文与片段总时长，没有独立携带每镜时长、景别；执行组装没有读取项目 `style`。成功的 H3 正文又绕过视频默认风格拼装。

建议在共享输入中显式区分“必须保持的事实、节奏和风格”与“允许优化的摄影表达”。未证实所有输出都会丢风格，应通过请求快照和人工样例评估，而不是直接宣称画质已受损。

定位：[H3 收集器](../../video-claw/video-claw/backend/core/agents/prompt_rewrite_agent.py#L254-L270)、[视频提示词选择](../../video-claw/video-claw/backend/core/agents/video_agent.py#L297-L304)。

### OP-05｜按实际可达能力清理说明与建立成本观测

自定义聊天客户端忽略 `web_search`，采用单条 user 消息，也未透传 temperature；界面／配置有字段不等于该路由支持该能力。`video/enhance.txt` 在已检索后端调用中未发现使用，修改它不能算现行视频主链优化。

推荐按模板／模型路由记录调用次数、token（供应商未返回时标为未知）、耗时、校验重试和 grounding 命中；维护模板可达性说明，不凭无引用结论直接删除兼容资源。`temperature` 维持当前预留语义，调优需独立方案与金标验证，不混入本轮接线修复。

定位：[自定义聊天客户端](../../video-claw/video-claw/backend/models/custom_llm.py#L25-L47)、[既有预留字段处置记录](minor-plan-07b4bdb-to-3ac13de.md#L46-L49)。
