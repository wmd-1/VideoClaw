# 用户空间上线与迁移流程

> 适用：把现有 VideoClaw 单机数据迁移到 PostgreSQL + MinIO 版本，并在迁移服务器完成上线。
> 本机已按本文流程演练过一次；迁移服务器请按顺序执行，不要跳步。

## 0. 迁移目标

- 会话/阶段检查点/任务/沙盒历史写入 PostgreSQL；
- 旧本地产物复制到 MinIO，`artifact_files` 记录 owner/object_key；
- 旧数据默认归属 `users.legacy_owner`（本文命令示例为 `local`）；
- 迁移不移动、不删除原 JSON 和本地文件，失败可回滚；
- 存量单机在 GUIP 未就绪前使用 `VC_USERS__MODE=single`。

## 1. 迁移前检查

```bash
cd <repo>
grep -E '^(USERS|POSTGRES|MINIO|VC_DATABASE__|VC_STORAGE__)' .env || true
docker compose ps
docker compose exec -T backend /app/.venv/bin/python -c \
  "from config import settings; print(settings.USERS_MODE, settings.USERS_LEGACY_OWNER)"
```

要求：

- PostgreSQL、MinIO、backend 均为 healthy/running；
- `.env` 中 `VC_USERS__LEGACY_OWNER` 与预期存量 owner 一致（默认 `local`）；
- 存量单机：`VC_USERS__MODE=single`；
- 迁移窗口内停止用户写入（至少停止后端或只读窗口）。

## 2. 备份（必须先做）

```bash
cd <repo>
STAMP=$(date +%Y%m%d-%H%M%S)
mkdir -p tmp_verify/backups/pre-migration-$STAMP

# PostgreSQL
docker compose exec -T postgres pg_dump -U videoclaw -d videoclaw \
  > tmp_verify/backups/pre-migration-$STAMP/postgres.sql

# 旧 JSON/本地状态（文件可能是 root 600，必须从 backend 容器内打包）
docker compose exec -T backend tar -C /app/code -czf - data \
  > tmp_verify/backups/pre-migration-$STAMP/legacy-json.tar.gz

ls -lh tmp_verify/backups/pre-migration-$STAMP
```

MinIO 若有既有对象，另做卷/`mc mirror` 备份：

```bash
# 示例：有 mc 时
mc mirror --overwrite <minio-alias>/videoclaw tmp_verify/backups/pre-migration-$STAMP/minio/
```

> 没有 MinIO 备份时至少保留 PostgreSQL dump + JSON tar；回滚时新上传对象不会被旧版本读取，但不要主动删除它们。

## 3. legacy import dry-run

```bash
docker compose exec -T backend /app/.venv/bin/python -m db.legacy_import \
  --fallback-owner local --files --dry-run
```

输出示例（本机演练）：

```text
INFO [dry-run] sessions=27 tasks=0 sandbox=121 files=99
```

如果 sessions/tasks/sandbox/files 数量与预期差异很大：

- 检查 `VC_USERS__LEGACY_OWNER`；
- 检查数据目录是否挂载到 `/app/code/data`；
- 不要直接进入正式导入。

## 4. 正式导入

```bash
docker compose exec -T backend /app/.venv/bin/python -m db.legacy_import \
  --fallback-owner local --files
```

本机演练结果：

```text
INFO imported sessions=27 tasks=0 sandbox=121 files=99
```

### 4.1 再执行一次验证幂等

```bash
docker compose exec -T backend /app/.venv/bin/python -m db.legacy_import \
  --fallback-owner local --files
```

预期 `files=0`，且 sessions/tasks/sandbox 行数不增加。第二次导入失败或重复上传，说明迁移不幂等，应停止上线。

## 5. 迁移后核验

### 5.1 DB 计数与 owner

```bash
docker compose exec -T postgres psql -U videoclaw -d videoclaw -c "
SELECT 'sessions' AS table_name, count(*) FROM sessions
UNION ALL SELECT 'session_stage_artifacts', count(*) FROM session_stage_artifacts
UNION ALL SELECT 'artifact_files', count(*) FROM artifact_files
UNION ALL SELECT 'pipeline_tasks', count(*) FROM pipeline_tasks
UNION ALL SELECT 'sandbox_records', count(*) FROM sandbox_records
UNION ALL SELECT 'saved_items', count(*) FROM saved_items;
"

docker compose exec -T postgres psql -U videoclaw -d videoclaw -c "
SELECT owner, count(*) FROM sessions GROUP BY owner;
SELECT count(*) AS missing_files FROM artifact_files WHERE missing_at IS NOT NULL;
"
```

本机演练：

```text

session_stage_artifacts 39
artifact_files 99
pipeline_tasks 0
sandbox_records 121
saved_items 0
owner local = 27
missing_files = 0
```

```bash
from db.database import fetch_all

s = get_storage(); s.ensure_bucket()
for row in fetch_all("SELECT object_key FROM artifact_files LIMIT 5"):
    print(row["object_key"], bool(s.stat(row["object_key"])))
PY
```

### 5.3 媒体与空间

```bash
# single 模式无需身份头；guip 模式请带 X-User-Login-Name
curl -s -o /dev/null -w '%{http_code}\n' \
  'http://127.0.0.1:<BACKEND_PORT>/api/sessions'
```

## 6. 前端与线上切换

### 6.1 构建（basePath/端口是构建期常量）

```bash
cd <repo>/video-claw/video-claw/frontend
export BACKEND_PORT=$(grep -E '^BACKEND_PORT=' ../../../.env | cut -d= -f2 | tr -d ' ')
BACKEND_INTERNAL_URL=http://backend:${BACKEND_PORT} \
NEXT_PUBLIC_BACKEND_PORT=${BACKEND_PORT} \
NEXT_PUBLIC_BASE_PATH=/Bocom_Video_Generation \
npm run build

mkdir -p .next-runtime
rm -rf .next-runtime/* .next-runtime/.[!.]*
cp -a .next/standalone/. .next-runtime/
mkdir -p .next-runtime/.next/static
cp -a .next/static/. .next-runtime/.next/static/
cp -a public .next-runtime/public
```

### 6.2 生效

```bash
cd <repo>
docker compose restart frontend
# 只改 config.yaml：restart backend
# 改 .env（尤其 VC_USERS__MODE / VC_DATABASE__ / VC_STORAGE__）：必须 up -d
docker compose up -d backend
```

存量单机先保持 `VC_USERS__MODE=single`；确认 GUIP 注入 `X-User-Login-Name` 后，再切：

```env
VC_USERS__MODE=guip
VC_USERS__ADMIN_LOGINS=<管理员登录名，逗号分隔>
```

`VC_USERS__MODE` 改动后必须 `docker compose up -d backend`，不能只 `restart`。

## 7. 回滚

回滚只用于迁移失败；先停止写入。

```bash
cd <repo>
docker compose stop backend frontend

# 1) 恢复 PostgreSQL（示例：清空 public 后恢复；执行前确认 dump 可用）
docker compose exec -T postgres psql -U videoclaw -d videoclaw -c \
  "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
docker compose exec -T postgres psql -U videoclaw -d videoclaw \
  < tmp_verify/backups/pre-migration-<STAMP>/postgres.sql

# 2) 恢复旧 JSON/本地状态（JSON 已是 backup 内 data 目录）
docker compose exec -T backend tar -C /app/code -xzf - \
  < tmp_verify/backups/pre-migration-<STAMP>/legacy-json.tar.gz

# 3) 若已有 MinIO 备份，恢复对象；没有则保留新增对象（旧版本不会读取）
docker compose up -d
```

回滚后旧版本应能启动并读取原 JSON；新版本写入的 DB 数据不会自动出现在旧版本中，这是预期行为。
